## 核心信息

### 摘要
现有的视频生成模型大多基于透视视频，只能合成场景的有限观测，导致完整性和全局一致性问题。本文提出了OmniRoam，一个可控的全景视频生成框架，利用全景表示每帧的丰富场景覆盖和固有的长期空间和时间一致性，实现长视野场景漫游。

框架从预览阶段开始，其中轨迹控制的视频生成模型从给定的输入图像或视频创建场景的快速概览。然后在精炼阶段，该视频在时间上扩展并在空间上上采样，以产生长距离、高分辨率的视频，从而实现高保真世界漫游。

为了训练模型，本文引入了两个全景视频数据集，包含合成和真实世界捕获的视频。实验表明，该框架在视觉质量、可控性和长期场景一致性方面始终优于最先进的方法，定性和定量评估都支持这一结论。本文还展示了该框架的几个扩展，包括实时视频生成和3D重建。

### 关键贡献
1. 引入了一个基于全局到局部预览-精炼设计的可控长视野全景视频生成框架，实现了连贯且可扩展的场景漫游。
2. 证明了全景表示和该设计在多个指标上优于基于透视的方法，并展示了使用该框架的扩展和应用。
3. 构建了一个可扩展的全景视频数据生成管道，并将发布一个带有相机轨迹的全景视频数据集，以支持大规模场景建模。
4. 提出了一种新的评估指标，循环一致性（loop consistency），用于量化场景级视频生成中的长期全局空间一致性，定量证明了全景表示的优势。

### Q1: 核心算法原理是什么？

**问题**: 这篇文章的核心算法原理是什么？请详细描述：1) 核心思想和动机，2) 主要技术方法，3) 算法流程和关键步骤，4) 输入输出。

**答案**:

#### 1) 核心思想和动机

**核心思想**: OmniRoam的核心思想是利用全景（panoramic）视觉表示作为大规模场景生成的基础，克服透视视频的局限性，实现长视野（long-horizon）场景漫游。

**动机**:
- **现有方法的问题**: 大多数现有场景生成方法基于透视视频，这些视频以人为中心视点为特征，由于其有限的视野覆盖，限制了物理环境的全面建模。自回归世界模型在处理大相机移动时，往往导致累积误差和时间漂移。
- **全景表示的优势**: 与透视视图不同，全景表示固有地提供整体场景覆盖和全局空间记忆，为在长期视频生成中保持空间和时间信息提供了自然和明确的机制。
- **设计哲学**: 有效的场景建模受益于全局到局部的设计：首先通过全景表示建立全局场景结构，然后通过增加的空间和时间分辨率逐步细化局部细节，从而产生既高保真又全局连贯的场景表示。

#### 2) 主要技术方法

OmniRoam采用**两阶段框架**：预览（Preview）阶段 + 精炼（Refine）阶段

##### 预览阶段（Preview Stage）
- **目的**: 从用户提供的图像或视频生成一个场景的粗略概览
- **输入**:
  - 输入图像/视频 `V_in ∈ ℝ^(f×3×H×W)`
  - 指定的相机轨迹（通过flow和scale两个正交因素控制）
- **输出**: 中分辨率（480×960）、加速播放速度的全景视频
- **关键技术**:
  1. **帧维度视频调节**: 采用帧维度调节策略确保严格的视觉连续性
  2. **分解的轨迹调节**: 将相机轨迹控制分解为两个正交分量：
     - **Flow（流）**: 指定移动的标准化方向，序列 `{d_k} k=1^f` 是单位向量
     - **Scale（尺度）**: 控制每时间步的全局步长大小，使用对数空间表示 `z_s = φ(log(s))`
  3. **基于Rectified Flow训练**: 使用 rectified flow 框架，前向过程在数据 `z_v` 和噪声 `ε ~ N(0, I)` 之间插值

##### 精炼阶段（Refine Stage）
- **目的**: 生成最终高质量全景视频，支持沉浸式、连贯的长视野场景漫游
- **输入**: 预览阶段生成的视频（加速播放）
- **输出**: 高分辨率（720×1440）、正常播放速度的全景视频
- **关键技术**:
  1. **尺度对齐和可见性掩码调节**:
     - 计算需要的段数 `n = ceil(s/s')`
     - 构建二进制可见性掩码 `m^(i) ∈ {0,1}^f` 选择预览帧作为条件
  2. **分段式精炼**: 将视频分成n段，每段单独精炼后拼接
  3. **分段式扩散**: 对每个分段分别应用扩散模型提高空间和时间分辨率

##### 全景数据生成管道
- **规范全景坐标系**: 设计了一个旋转不变的坐标系，通过消除相机自旋转（roll、pitch、yaw），仅通过相对于ERP中心的平移（x,y,z）定义轨迹
- **混合数据集**:
  - **真实世界数据**: 约2000个手持全景视频（500万帧），包含酒店、学校和户外景观等多样化环境
  - **合成数据**: 从3DGS场景渲染1000个场景，使用自动化管道合成物理可行的轨迹

#### 3) 算法流程和关键步骤

**整体流程**:

```
输入图像/视频 + 相机轨迹
        ↓
┌─────────────────────────────┐
│      预览阶段            │
│  - 分解轨迹(flow+scale)   │
│  - 生成加速中分辨率视频    │
│  - 480×960, 81帧        │
└─────────────────────────────┘
        ↓
┌─────────────────────────────┐
│      精炼阶段            │
│  - 尺度对齐             │
│  - 分段处理              │
│  - 可见性掩码调节        │
│  - 提升时空分辨率        │
│  - 720×1440, 正常播放    │
└─────────────────────────────┘
        ↓
输出高质量长视野全景漫游视频
```

**关键算法步骤**:

**Step 1: 输入编码**
```python
# 使用3D VAE编码器编码输入和目标视频
z_in = E_v(V_in)  # 输入潜在表示
z_v = E_v(V_v)     # 目标潜在表示
```

**Step 2: 轨迹条件嵌入**
```python
# Scale嵌入（全局步长）
z_s = φ(log(s))  # 对数空间处理宽范围速度

# Flow嵌入（方向序列）
z_d = E_c(D)     # D = {d_k} k=1^f 单位向量序列
```

**Step 3: 预览阶段生成**
```python
# Rectified Flow前向过程
z_t = t * z_v + (1-t) * ε  # 仅目标添加噪声

# 帧维度拼接
z_concat = [z_in, z_t]_frame  # z_in保持干净作为条件

# 速度场预测
v_Θ([z_in, z_t]_frame, t, c)  # c = {z_d, z_s}

# 损失函数
L_preview = E[||v_Θ(...) - (z_v - ε)||²]
```

**Step 4: 精炼阶段分段**
```python
# 计算分段数量
n = ceil(s / s')  # s=预览尺度, s'=目标尺度

# 每段生成可见性掩码
m_j^(i) = 1 if j0^(i) ≤ j < j0^(i) + w else 0
# w = ceil((f-1)/n), j0^(i) = (i-1)w
```

**Step 5: 分段精炼**
```python
# 掩码条件潜在
z̃_p^(i) = z_p ⊙ m'^(i)  # 逐元素相乘

# 分段精炼
L_refine = E[||v_Φ([z̃_p^(i), z_t']_frame, t) - (z'_v - ε)||²]
```

**Step 6: 视频拼接**
```python
V = [V^(1), V^(2), ..., V^(n)]  # 拼接所有精炼段
```

#### 4) 输入输出

**输入**:
- **视觉输入**: 单张全景图像或短视频片段
- **相机轨迹**: 用户指定的相机运动轨迹（3D平移向量序列）
- **轨迹参数**: Flow（方向）+ Scale（速度/步长）

**输出**:
- **预览阶段**: 480×960分辨率、加速播放（scale=1.1-8.0）、81帧全景视频
- **精炼阶段**: 720×1440分辨率、正常播放（scale=1.0）、长视野全景视频（可达641帧）
- **扩展输出**: 
  - 实时预览版本（7秒生成81帧）
  - 3DGS重建场景

**关键技术参数**:
- 预览阶段: 480×960, 81帧, Wan2.1-1.3B微调
- 精炼阶段: 720×1440, 81帧/段, Wan2.1-1.3B微调
- 训练数据: 2000真实视频 + 1000合成场景, 共500万帧
- 轨迹类型: 前进、后退、左、右、S形、循环、真实轨迹

### Q2: 这篇文章与Spatial AGI有什么关系？

**问题**: 这篇文章与通用空间智能（Spatial AGI）有什么关系？请分析：1) 如何理解和表示空间，2) 如何处理空间关系，3) 对Spatial AGI有什么启发，4) 可以应用到哪些Spatial AGI场景（机器人、AR/VR等）。

**答案**:

#### 1) 如何理解和表示空间

OmniRoam在空间理解和表示方面为Spatial AGI提供了全新的范式：

**全景表示 vs 透视表示**:
- **全景表示的优势**:
  - **全局视野**: 单帧包含360度全景信息，提供完整的场景上下文
  - **全局空间记忆**: 每帧都能看到整个环境，无需累积记忆
  - **旋转不变性**: 相机旋转对应像素移位而非几何遮挡，简化了表示
- **透视表示的局限**:
  - **有限视野**: 窄视角（通常90-120度），只能看到场景部分
  - **累积误差**: 需要通过时间累积来理解空间，导致漂移
  - **全局一致性困难**: 大相机运动时难以维持空间结构

**规范全景坐标系**:
- **旋转不变设计**: 消除相机自旋转（roll、pitch、yaw），仅通过平移（x,y,z）定义轨迹
- **锚点中心**: 以ERP中心（φ=0, θ=0）为参考点
- **简化空间推理**: 视觉动态完全由相对于锚点的空间平移驱动

**对Spatial AGI的意义**:
- **空间表示的范式转变**: 从以人为中心的透视视角转向上帝视角的全景表示
- **显式空间建模**: 通过全景表示，空间结构显式存在于每帧中
- **可解释性**: 轨迹分解为flow和scale，提供了可解释的空间控制接口

#### 2) 如何处理空间关系

OmniRoam在处理空间关系方面展现了Spatial AGI所需的关键能力：

**长期空间一致性**:
- **循环一致性指标**: 提出了新的评估指标 `C_loop = (1-S2)/(1-S1)` 来量化长期全局空间一致性
  - S1: 循环闭合分数（首尾帧相似度）
  - S2: 中间帧分数（中间帧与首尾的相似度）
- **实验验证**: 在641帧的长视频中，OmniRoam能准确返回初始位置，保持空间结构

**轨迹控制**:
- **分解式控制**: Flow（方向）+ Scale（速度）的正交分解提供了精细的空间控制
- **假设约束**: 
  - 匀速: 相机沿轨迹以几乎恒定速度移动
  - 固定方向: 相机方向在序列中保持不变
- **物理可行性**: 数据管道确保轨迹物理可行（避开障碍物、合理速度）

**多尺度空间理解**:
- **全局到局部**: 先建立全局场景结构（预览），再细化局部细节（精炼）
- **自适应分辨率**: 根据需要动态调整时空分辨率
- **分段处理**: 长视频分段生成，避免计算瓶颈

**空间-时间耦合**:
- **帧维度调节**: 确保空间和时间的一致性耦合
- **可见性掩码**: 精炼阶段使用掩码选择相关预览帧
- **时序扩展**: 从加速播放扩展到正常播放，保持空间连续性

#### 3) 对Spatial AGI有什么启发

OmniRoam为Spatial AGI提供了以下关键启发：

**启发1: 全景表示作为空间记忆**
- **全局空间记忆**: 全景每帧包含完整场景，可作为空间智能体的"外部记忆"
- **显式3D意识**: 全景感知让智能体有"我在世界哪里"的明确感知

**启发2: 两阶段生成策略**

**启发3: 轨迹分解和控制**

**启发4: 评估指标的革新**
- **超越传统指标**: FVD、FID等无法捕获长期空间一致性

## 🎯 核心问题：全景表示能否成为Spatial AGI的空间基础表示？

### 为什么这个问题最重要？

这个问题触及了Spatial AGI的根本性挑战：**如何表示和利用空间信息**。OmniRoam展示了全景表示在视频生成中的强大能力，但这能否推广到Spatial AGI的更广泛任务中？

### 问题维度分析

#### 维度1: 表示能力

**全景表示的优势**:
1. **全局上下文**: 单帧包含完整360度信息
2. **旋转不变性**: 相机旋转是像素移位而非几何变换
3. **显式空间结构**: 空间关系显式存在于表示中

**潜在局限**:
1. **分辨率损失**: 360度信息分配到固定像素，每个方向的分辨率有限
2. **几何失真**: ERP投影导致极地变形和变形
3. **深度信息缺乏**: 原始全景不包含显式深度

**关键问题**: 
- 全景表示是否足够丰富以支持复杂空间推理？
- 能否从全景表示中提取显式3D几何？
- 如何平衡全景的全局性与透视的局部精度？

#### 维度2: 计算效率

**当前情况**:
- 预览阶段: 480×960分辨率，约5分钟生成81帧
- 实时版本: 7秒生成81帧（通过知识蒸馏）
- 精炼阶段: 分段处理，显著增加计算成本

**挑战**:
- **实时性要求**: 机器人导航需要毫秒级响应，当前方法延迟过高
- **资源限制**: 边缘设备（AR眼镜、机器人）计算资源有限
- **可扩展性**: 长视频（641帧）需要分段处理，增加复杂度

**关键问题**:
- 能否实现真正的实时全景生成（<100ms）？
- 如何优化分段处理策略以减少延迟？
- 能否在边缘设备上部署？

#### 维度3: 泛化能力

**当前范围**:
- **训练数据**: 主要是室内场景（酒店、学校）和一些户外景观
- **轨迹类型**: 7种预定义轨迹（前进、后退、左、右、S形、循环、真实）
- **场景复杂度**: 相对简单场景，未测试极端复杂情况

**泛化挑战**:
- **域外场景**: 工业环境、自然地形、水下等未见场景
- **复杂轨迹**: 6-DoF复杂运动、动态调整
- **动态对象**: 包含人、动物、车辆等移动对象的场景

**关键问题**:
- 全景表示在不同环境中的鲁棒性如何？
- 能否处理高度动态的场景？
- 如何实现零样本泛化到全新环境类型？

#### 维度4: 与其他表示的融合

**当前方法**: 纯全景表示

**潜在融合方向**:
1. **全景+深度**: 结合深度估计提供显式3D信息
2. **全景+语义**: 结合语义分割提供语义理解
3. **全景+地图**: 结合拓扑地图提供全局路径规划
4. **多尺度表示**: 全景（全局）+ 透视（局部细节）

**关键问题**:
- 如何有机融合异构表示？
- 融合表示如何保持一致性？
- 哪种融合策略最有效？

#### 维度5: 可控性与自主性的平衡

**当前状态**:
- **用户控制**: 轨迹完全由用户指定
- **生成角色**: 主要是"渲染"用户意图，非自主决策

**Spatial AGI需求**:
- **自主探索**: 智能体需要自主决定探索路径
- **目标导向**: 根据任务目标（"找出口"、"找到人"等）自主规划
- **适应性**: 根据环境反馈实时调整策略

**关键问题**:
- 如何从用户控制扩展到自主决策？
- 全景表示能否支持目标导向的空间推理？
- 如何评估自主决策的质量？

## 核心技术发现

### 发现1: 全景表示的长期一致性优势

**实验证据**:
- 循环一致性指标: OmniRoam在641帧长视频中显著优于baseline
- 3DGS重建: 从生成全景视频重建的3D场景结构一致
- 定性分析: 长视频返回初始位置时视觉高度一致

**技术原因**:
1. **全局视野**: 每帧包含完整360度信息，无需时间累积
2. **旋转不变**: 相机旋转是像素移位，不改变几何结构
3. **显式空间**: 全景表示显式编码空间结构

**启示**:
- 全景表示天然适合长期空间一致性
- 为Spatial AGI提供了新的表示选择
- 可能解决透视表示的累积误差问题

### 发现2: 两阶段生成的效率与质量平衡

**实验证据**:
- 预览阶段: 5分钟生成81帧（480×960）
- 精炼阶段: 分段处理提升到720×1440
- 实时版本: 知识蒸馏后7秒生成81帧

**技术优势**:
1. **候选生成**: 快速生成多个候选方案
2. **用户选择**: 用户可以选择最佳配置
3. **分段优化**: 避免长视频的计算瓶颈

**启示**:
- 两阶段设计是视频生成的有效策略
- 知识蒸馏可以实现实时生成
- 分段处理支持任意长度视频

### 发现3: 轨迹分解的简化效果

**实验证据**:
- Flow+Scale分解简化了训练和推理
- 精炼阶段只需调整scale，无需轨迹向量
- 7种预定义轨迹实现可控生成

**技术优势**:
1. **正交控制**: 方向和速度独立控制
2. **直观接口**: Flow+Scale易于理解和调整
3. **简化精炼**: scale对齐比完整轨迹对齐简单

**启示**:
- 复杂控制可以分解为简单正交因素
- 可解释控制接口对实际应用重要
- 分解设计支持模块化和可扩展性

### 发现4: 混合数据集的互补性

**实验证据**:
- 真实数据: 2000视频，500万帧，多样化环境
- 合成数据: 1000场景，精确几何监督
- 联合训练优于单独使用任一数据集

**技术优势**:
1. **多样性**: 真实数据提供视觉多样性
2. **精确性**: 合成数据提供精确轨迹
3. **鲁棒性**: 混合训练提升泛化能力

**启示**:
- 真实+合成是有效的数据策略
- 物理约束的合成数据提升质量
- 大规模数据集对场景建模必要

### 发现5: 循环一致性指标的有效性

**实验证据**:
- 量化了长期空间一致性
- 区分了不同方法的质量
- 与人类判断高度相关

**技术创新**:
1. **任务特定**: 直接测量空间理解质量
2. **可解释**: C_loop=(1-S2)/(1-S1)有明确物理意义
3. **通用性**: 可应用于任何场景生成方法

**启示**:
- 传统指标（FVD、FID）不足以评估空间质量
- 需要开发任务特定的评估指标
- 新指标可以推动领域进步

## 与Spatial AGI的关系

### 直接贡献

#### 1. 全景表示的范式转变

**传统范式**（Perspective-Based）:
- 以人为中心的透视视角
- 有限视野（通常<120度）
- 累积误差和时间漂移
- 全局一致性困难

**新范式**（OmniRoam）:
- 全局视野的 panoramic 视角
- 360度完整场景覆盖
- 每帧显式包含空间结构
- 天然长期一致性

**对Spatial AGI的意义**:
- **表示创新**: 提供了新的空间表示选择
- **理论基础**: 为空间表示建立了新范式
- **实践指导**: 为实际应用提供了可验证的方案

#### 2. 长期空间一致性解决方案

**问题**: 透视视频在大相机运动时累积误差
**解决方案**: 全景表示的固有全局记忆
**效果**: 641帧视频保持空间结构，准确返回初始位置

**对Spatial AGI的意义**:
- **核心挑战**: 长期空间一致性是Spatial AGI的关键需求
- **可行方案**: OmniRoam证明全景表示可以解决这个挑战
- **实际应用**: 可直接应用于机器人导航、AR/VR等

#### 3. 可控视频生成框架

**问题**: 现有方法可控性差，难以控制相机轨迹
**解决方案**: Flow+Scale分解 + 两阶段生成
**效果**: 7种轨迹可控生成，包括复杂循环轨迹

**对Spatial AGI的意义**:
- **交互接口**: Flow+Scale提供了直观的可控接口
- **灵活性**: 支持用户自定义轨迹
- **实用性**: 可用于场景预览、路径规划等

#### 4. 大规模场景建模能力

**问题**: 现有方法难以处理大规模场景
**解决方案**: 分段处理 + 尺度扩展
**效果**: 支持641帧长视频，覆盖大规模场景

**对Spatial AGI的意义**:
- **可扩展性**: 证明全景表示可扩展到大规模
- **应用范围**: 支持建筑、城市、自然场景等
- **实用性**: 可用于城市规划、建筑预览等

### 技术启发

#### 启发1: 全局到局部的生成策略

**核心思想**: 先建立全局结构，再细化局部细节
**实现方式**: 预览（全局）→ 精炼（局部）
**效果**: 平衡了效率和 质量

**对Spatial AGI的启发**:
- **空间理解层次化**: 从粗到细逐步建立空间模型
- **资源分配**: 将计算资源分配到最重要部分
- **适应性**: 根据需要动态调整精度

#### 启发2: 分段处理的必要性

**原因**: 长视频计算成本高，难以一次性生成
**方法**: 将长视频分成段，分段生成再拼接
**效果**: 支持641帧长视频

**对Spatial AGI的启发**:
- **分治策略**: 将复杂任务分解为可管理子任务
- **可扩展性**: 支持任意长度/规模
- **容错性**: 单段失败不影响整体

#### 启发3: 轨迹分解的通用性

**核心思想**: 将复杂控制分解为简单正交因素
**实现**: Flow（方向）+ Scale（速度）
**效果**: 简化训练和推理

**对Spatial AGI的启发**:
- **控制抽象**: 将复杂控制抽象为简单接口
- **模块化**: Flow和Scale可独立优化
- **通用性**: 可扩展到其他控制空间

#### 启发4: 评估指标的创新

**传统指标**: FVD、FID、SSIM等
**局限性**: 不捕获长期空间一致性
**新指标**: 循环一致性 C_loop

**对Spatial AGI的启发**:
- **任务特定**: 开发针对空间理解任务的指标
- **可解释性**: 指标应有明确物理意义
- **推动作用**: 新指标可以推动领域进步

#### 启发5: 混合数据的互补性

**真实数据优势**: 视觉多样性、真实场景复杂度
**合成数据优势**: 精确监督、大规模、可控性
**混合训练**: 结合两者优势

**对Spatial AGI的启发**:
- **数据策略**: 真+合成是有效策略
- **物理约束**: 合成数据应物理可行
- **可扩展性**: 数据生成管道应可扩展

### 1. 最有趣的发现

**全景表示的全局记忆效应**:
- **意外之处**: 我原以为360度视野只是"看得更多"，但实际上它提供了"全局空间记忆"

**为什么重要**:
- 这彻底改变了空间推理的方式
- 消除了累积误差这个根本问题
- 为长期一致性提供了自然的机制

**后续思考**:

### 设计分析结果 (Table 2)

**表示选择** (全景 vs 透视):
- **全景**: 更好的视觉质量、轨迹控制、循环一致性
- **透视**: 所有指标都下降
- **影响**: 有限视野难以保持全局场景结构

**生成策略** (全局到局部 vs 自回归):

- **自回归**: 循环一致性分数几乎减半
- **原因**: 误差累积跨段

### 核心发现总结

1. **全景表示的固有优势**: 360度视野提供全局空间记忆，天然适合长期一致性

5. **混合数据互补性**: 真+合成结合实现最佳训练效果

### A. 实现细节

**模型架构**:

- 优化器: AdamW

- 梯度裁剪: 1.0
- 混合精度: FP16

**推理细节**:
- 采样步数: 50步
- 分类器自由引导: 1.5
- 温度: 1.0
- CFG scale: 7.5

### B. 数据生成管道

**真实数据流程**:
1. 手持相机捕获全景视频
2. 重力对齐和稳定
3. COLMAP轨迹估计
4. 尺度过滤和归一化
5. 数据增强（随机裁剪、翻转等）

**合成数据流程**:
1. 3DGS场景加载
2. 有效区域计算（障碍物过滤）
3. 候选航点生成（覆盖50%自由空间）
4. 恒速轨迹生成
5. 全景渲染（ERP投影）
6. 姿态和轨迹记录

### C. 扩展实验

**实时预览器**:
- 蒸馏方法: Distribution matching loss
- 学生模型: 轻量级DiT
- 训练数据: 预览模型生成数据
- 训练时长: 200k steps

**3DGS重建**:
- 输入: 100帧全景视频
- 视角提取: 每帧5个透视视图（120° FoV, 512×512）
- 重建方法: 3D Gaussian Splatting
- 输出: 完整3DGS场景

### D. 评估协议

**视觉质量指标计算**:
- FAED: 使用预训练auto-encoder特征空间
- SSIM: 标准SSIM公式，窗口大小11
- LPIPS: 使用预训练VGG或AlexNet网络

**轨迹控制评估**:
- 帧窗口: 20-25, 50-55, 70-75, 610-615, 630-635
- 对齐方法: 时间戳对齐
- PSNR计算: 标准PSNR公式

**循环一致性计算**:
- 缓冲大小: P=5帧
- 相似度度量: CLIP embedding cosine similarity
- 公式: C_loop = (1-S2)/(1-S1)
- S1: 首尾P帧平均相似度
- S2: 中间帧与首尾平均相似度
