## 核心信息

### 摘要

近年来，视频扩散技术的进步使得能够模拟交互环境的"世界模型"得以发展。然而，这些模型主要局限于单智能体场景，无法同时控制场景中的多个智能体。在这项工作中，我们解决了现有视频扩散模型中的一个基本问题——动作绑定（action binding），即模型难以将特定动作与其对应的主体正确关联。

为此，我们提出了ActionParty，一个用于生成视频游戏的可动作控制的多主体世界模型。它引入了主体状态token（subject state tokens），即持久捕获场景中每个主体状态的潜在变量。通过空间偏置机制（spatial biasing mechanism）联合建模状态token和视频潜在表示，我们将全局视频帧渲染与个体动作控制的主体更新解耦。

我们在Melting Pot基准测试上评估ActionParty，展示了第一个能够在46个不同环境中同时控制多达7个玩家的视频世界模型。我们的结果显示在动作跟随准确性和身份一致性方面有显著提升，同时能够在复杂交互中稳健地自回归跟踪主体。

### 关键贡献

1. **提出ActionParty框架**：一个新颖的自回归视频生成器，用于生成游戏模拟。我们联合建模视频帧和每个主体的状态，并引入注意力掩码以强制执行动作-主体对应关系，从而实现一致的多主体动作控制。

2. **引入基于RoPE偏置的动作绑定机制**：将主体状态锚定到视频中的特定空间坐标，实现可靠的主体定位。

3. **首次展示多主体世界模型**：在46个不同环境中同时控制多达7个主体，在动作跟随和主体一致性方面实现卓越性能。

## Q1: 核心算法原理

### 1) 核心思想和动机

#### 核心问题：动作绑定（Action Binding）

论文的核心动机是解决视频扩散模型在多主体场景中的**动作绑定失败**问题。当场景中存在多个可控制主体时，模型必须能够正确地将每个控制信号（通常是动作）与其对应的主体关联。然而，现有模型面临一个根本性挑战：

**问题诊断**：
- 视频扩散模型本质上在像素空间中隐式地定义主体
- 除了视觉外观外，没有明确的主体表示来锚定动作
- 当给定多个条件信号时，扩散模型经常忽略其中一些或合并多个信号

**具体失败案例**：
作者分析了一个由两个基本形状在实心背景上移动的简化环境：
- 测试提示词："红色三角形向右移动，蓝色正方形向上移动。然后红色三角形向下移动，蓝色正方形向左移动。然后红色三角形向上移动，蓝色正方形向右移动。然后红色三角形向左移动，蓝色正方形向下移动。"

**结果**：
- 即使是最先进的视频生成器（如Veo 3）也无法正确执行这一系列基本命令
- 当多个动作在序列中描述时，失败更加显著
- 这种失败与现有扩散模型中属性绑定的根本性限制有关

#### 核心思想：显式主体状态表示

ActionParty的核心创新在于引入**显式的主体状态表示**，将世界模型的预测问题从单纯的条件视频生成重构为：

**传统世界模型**：
```
x_{t+1} ~ f_θ(x_{t+1} | x_{0:t}, a_{0:t})
```

**ActionParty联合建模**：
```
x_{t+1}, z_{t+1} ~ f_θ(x_{t+1}, z_{t+1} | x_{0:t}, a_{0:t}, z_{0:t})
```

其中：
- `x`：视频帧序列
- `z`：主体状态（每个主体的潜在状态变量）
- `a`：动作输入

通过引入显式的主体状态`z`，模型获得了：
1. **明确的主体标识**：每个主体有独立的状态token
2. **持久的隐式状态**：状态在整个时间序列中持续存在
3. **动作-主体解耦**：通过注意力机制精确控制信息流

### 2) 主要技术方法

#### 2.1 主体状态Token（Subject State Tokens）

**定义**：
主体状态token是一组潜在变量`{z_t^i}`，用于持久捕获场景中每个主体`S_i`在时间步`t`的状态。

**状态表示**：
在大多数游戏环境中，作者发现主体的**空间位置**足以区分它们，因为两个主体不能占据相同位置。因此，论文中将主体状态定义为其2D坐标：
```
z_t^i = (h_t^i, w_t^i)
```

**坐标编码器和解码器**：
- 编码器：`W_enc ∈ R^(2×1536)` - 将2D坐标映射到视频DiT的内部维度
- 解码器：`W_dec ∈ R^(1536×2)` - 将潜在表示解码回坐标空间以计算流匹配损失

**坐标归一化**：
为了使坐标与VAE编码的视频潜在表示具有相似的统计特性，作者对坐标进行归一化（重新中心化并按因子4.0缩放）。

#### 2.2 生成式游戏引擎范式

ActionParty受到标准游戏引擎的启发，将单帧生成分解为两个不同阶段：

**阶段1：状态更新（State Update）**
- **目标**：根据特定主体的动作更新其状态
- **实现**：通过交叉注意力（Cross-Attention）层处理动作输入
- **关键机制**：使用注意力掩码强制执行严格的主体-动作绑定

**阶段2：渲染（Rendering）**
- **目标**：使用更新后的主体状态合成视频帧
- **实现**：通过自注意力（Self-Attention）层进行视频帧渲染
- **关键机制**：使用空间RoPE偏置将主体状态锚定到视频中的正确位置

#### 2.3 注意力掩码机制

**交叉注意力掩码（M_CA）**：
```
主体i的状态token z^i 仅允许关注其对应的动作嵌入 a^i
```

**关键特性**：
- **严格绑定**：主体token只能关注自己的动作，阻塞所有不匹配动作和主体token之间的通信
- **防止泄漏**：避免不同主体之间的信息混合
- **文本嵌入限制**：文本嵌入c仅允许关注视频tokenx，以保留预训练模型的容量

**自注意力掩码（M_SA）**：
```
- 所有主体token可以关注视频token（从环境中读取信息）
- 阻止主体到主体的通信（避免混合不同主体的状态）
- 视频token可以关注所有主体token（使用所有主体的状态进行帧合成）
```

#### 2.4 空间RoPE偏置（Spatial RoPE Biasing）

**问题**：
自注意力掩码`M_SA`虽然防止了主体混合，但没有显式地将视频中的主体与其状态token链接。

**解决方案**：
利用**3D Rotary Position Embeddings（RoPE）**来消除这种映射的歧义。

**实现细节**：

1. **视频token旋转**：
   - 视频token在帧`x_t`中的位置`p = (h, w)`接收旋转`R(t, h, w)`

2. **主体token旋转**：
   - 使用前一时间步的主体位置`z_{t-1}^i = (h_{t-1}^i, w_{t-1}^i)`
   - 对主体token`z_t^i`应用旋转`R(t, h_{t-1}^i, w_{t-1}^i)`

3. **使用前一位置的原因**：
   - 当前位置`z_t^i`正在被去噪，在当前阶段是未知的
   - 但`z_{t-1}^i`应该接近真实的`z_t^i`，确保靠近主体的视频token被偏置关注对应的主体状态token

**效果**：
模型的任务从全局消歧被大大简化为在单个动作半径内的局部精化，因为RoPE偏置确保了主体状态token只能与该主体附近的视频token交互。

#### 2.5 架构扩展

**模型基础**：
- 基于Wan2.1-1.3B（开源文本到视频DiT）进行微调
- 类似MMDiT（SD3）的架构，联合去噪x和z

**token序列**：
```
[视频token序列] + [主体1状态token序列] + [主体2状态token序列] + ...
```

**训练效率**：
- 使用FlexAttention实现注意力掩码
- 每个主体仅添加`N×T`个额外token
- 对于T=5的7玩家场景，仅增加6%的开销（40个额外token）
- 相比其他为每个主体生成多个场景视角的方法显著更高效

### 3) 算法流程和关键步骤

#### 训练流程

**步骤1：预训练（无动作控制）**
- 目的：加速模型收敛，使模型适应自回归设置
- 设置：仅提供文本条件（游戏的简单描述），无动作控制、主体状态或架构修改
- 数据：所有游戏（|G|=46）
- 训练：22.5k步，批量大小64

**步骤2：动作控制微调**
- 目的：添加完整的ActionParty机制（主体状态、注意力掩码、RoPE偏置）
- 数据：游戏玩法视频（46个不同的2D游戏）
- 动作空间：25个不同的离散动作（7个基础动作：Idle、Move×4、Turn×2、Interact）
- 每个游戏：2000个视频，分辨率512×512
- 训练：65k步，批量大小64
- 上下文长度：T=5个时间步（对应每个rollout 4个唯一动作）
- 损失函数：Adam优化器，在`x_{t+1}^i`和`z_{t+1}^i`上计算的流匹配损失

**步骤3：采样策略**
- 每个游戏rollout：使用随机动作或预训练策略
- 确保多样性：为每个游戏生成多样化的rollout

#### 推理流程

**步骤1：初始化**
- 提供初始帧`x_0`
- 提供初始主体位置`{z_0^i}_{i=1}^{N_g}`
- **重要**：没有此初始化，在许多实体外观相同的环境中区分主体是不可能的

**步骤2：自回归rollout**
```
给定上下文 (x_0 || x̂_{1:t}, z_0^i || ẑ_{1:t}^i):
1. 预测下一视频帧 x_{t+1}
2. 预测下一状态变量 z_{t+1}
3. 使用滑动窗口：当t > T时，丢弃最旧的帧
   确保上下文窗口大小永远不会超过T-1
```

**步骤3：采样参数**
- 采样步数：20步
- 时间步偏移：5.0
- 最大主体数：场景中最多7个主体（用零填充额外的主体状态）

#### 评估流程

**步骤1：数据收集**
- 每个游戏：230个rollouts（每个游戏5个）
- 确保多样性：
  - t < 2时，强制`a_t^i ~ {Move, Turn}`以离开初始状态
  - t ≥ 2时，至少分配一个主体"Interact"动作

**步骤2：指标计算**

**a. 移动精度（Movement Accuracy, MA）**：
- 从连续视频帧中提取每个主体的移动（左、右、上、下或静止）
- 与输入动作进行比较
- 实现：训练简单的主体检测器，在原始视频帧上达到接近100%的准确率

**b. 效果精度（Effect Accuracy, EA）**：
- 评估上下文相关的"Interact"动作的效果
- 提取以真实玩家位置为中心的3×3瓦片补丁
- 使用SSIM评估与前一帧的不相似度
- 阈值：补丁SSIM ≥ 0.85以检测执行的动作

**c. 主体保持（Subject Preservation, SP）**：
- 测量在生成结束时保留了多少主体

**d. 检测率（Detection Rate, DR）**：
- 测量主体位置与真实值对齐的步骤百分比

**e. 视觉质量指标**：
- PSNR、LPIPS、FVD（与真实视频比较）

**f. 状态精度**：
- 计算预测坐标`z_t`与真实位置之间的L2距离

### 4) 输入输出

#### 输入

**1. 视频上下文**：
- 初始视频帧序列`x_{0:t}`
- 分辨率：512×512
- 通过VAE编码器压缩为潜在表示

**2. 主体状态上下文**：
- 初始主体状态序列`z_{0:t}`
- 每个主体状态：2D坐标`(h, w)`

**3. 动作输入**：
- 离散动作序列`a_{0:t} = {a_t^i}_{i=1}^{N_g}`
- 动作空间：25个不同动作
  - 7个基础动作：Idle、Forward、Backward、Strafe Left、Strafe Right、Turn Left、Turn Right、Interact
  - 动作是相对的：取决于主体的朝向

**4. 文本条件**：
- 游戏环境描述`c`
- 由LLM从Melting Pot论文和每个游戏的视频中生成

**5. 元信息**：
- 游戏环境标识
- 主体数量`N_g`（最多7个）
- 最大主体数（用于零填充）

#### 输出

**1. 下一视频帧**：
- 预测的视频帧`x_{t+1}`
- 分辨率：512×512
- 包含所有主体的渲染

**2. 下一主体状态**：
- 预测的主体状态`z_{t+1} = {z_{t+1}^i}_{i=1}^{N_g}`
- 每个主体状态：2D坐标`(h, w)`
- 用于下一时间步的RoPE偏置

**3. 累积输出（自回归rollout）**：
- 完整视频序列：`x_0, x_1, ..., x_T`
- 完整状态轨迹：`z_0, z_1, ..., z_T`
- 支持通过滑动窗口扩展到长horizon（如20步）

## Q2: 与Spatial AGI的关系

### 1) 如何理解和表示空间

#### 显式空间坐标表示

ActionParty引入了一种**显式的空间坐标表示**方法，这对于Spatial AGI具有重要意义：

**坐标作为状态**：
```
z_t^i = (h_t^i, w_t^i)
```

这种表示具有以下特点：
- **绝对空间定位**：每个主体在2D网格上有明确的坐标
- **离散化空间**：使用16×16网格（适应512×512分辨率）
- **空间可追踪**：状态在整个时间序列中持久存在

**Spatial AGI的启示**：
1. **空间显式化**：Spatial AGI系统需要将空间关系从隐式表示（像素级）转换为显式表示（坐标级）
2. **空间量化**：离散网格提供了一种处理连续空间的有效方法
3. **空间持久性**：主体状态token提供了一种持久的空间表示，跨越时间步

#### 多主体空间共存

ActionParty处理**多主体在同一空间中的共存和交互**，这是Spatial AGI的核心场景：

**空间区分挑战**：
- 视觉相似的主体需要通过位置区分
- 主体不能占据同一空间位置
- 空间关系（相对位置、距离）影响交互

**解决方案**：
- 独立的状态token为每个主体提供独特的空间标识
- RoPE偏置机制将状态token锚定到正确的空间坐标
- 注意力掩码防止主体之间的信息泄漏

**Spatial AGI的启示**：
1. **多实体空间管理**：需要为多个实体提供独立的空间表示
2. **空间唯一性约束**：确保不同实体不冲突地占用空间
3. **空间-动作绑定**：将动作正确地应用到正确的空间位置

### 2) 如何处理空间关系

#### 相对动作与绝对空间

ActionParty的一个重要特征是动作是**相对于主体朝向**的，而不是绝对方向：

**动作空间**：
- Forward：在主体朝向的方向上移动一个瓦片
- Backward：向后移动
- Strafe Left/Right：左右移动
- Turn Left/Right：旋转朝向

**空间推理需求**：
```
主体的朝向只能从原始视频帧推断
→ 模型必须理解视觉信息才能获得正确的动作结果
→ 而不是学习绝对方向指令如"向上移动"
```

**Spatial AGI的启示**：
1. **相对空间推理**：理解动作如何相对于当前状态改变空间位置
2. **视觉-空间映射**：从视觉观察中提取空间关系（如朝向、相对位置）
3. **上下文依赖性**：动作的效果取决于当前空间状态（位置、朝向、遮挡）

#### 空间交互建模

ActionParty处理复杂的**空间交互**，这是Spatial AGI的核心能力：

**交互类型**：
1. **移动交互**：改变主体的空间位置
2. **环境交互**：与静态对象交互（Interact动作）
   - 激活主体前方的瓦片
   - 发射光束
   - 与物体交互
3. **多主体交互**：多个主体在空间中的同时动作

**空间效果检测**：
- Effect Accuracy (EA)指标评估"Interact"动作的空间效果
- 提取3×3瓦片补丁，使用SSIM检测视觉变化
- 考虑空间上下文（如墙壁可能阻止效果）

**Spatial AGI的启示**：
1. **动作-空间效果预测**：预测动作如何在空间中产生效果
2. **交互区域建模**：理解动作在空间中的影响范围
3. **上下文感知**：考虑空间约束（如障碍物、边界）

#### 空间偏置机制

RoPE偏置机制提供了一种**基于空间的注意力引导**方法：

**工作原理**：
```
主体token z_t^i 使用旋转 R(t, h_{t-1}^i, w_{t-1}^i)
→ 被偏置关注相同空间坐标的视频token
```

**空间约束**：
- 主体状态token只能与附近（相同坐标）的视频token交互
- 防止全局消歧，简化为局部精化
- 确保动作-主体绑定在正确的空间位置

**Spatial AGI的启示**：
1. **空间局部性**：利用空间局部性简化决策
2. **空间注意力引导**：引导模型关注相关的空间区域
3. **空间-信息解耦**：将全局空间问题分解为局部子问题

### 3) 对Spatial AGI的启发

#### 显式状态表示的价值

ActionParty证明了**显式状态表示**的价值：

**从隐式到显式**：
- 传统方法：仅在像素空间中隐式表示主体
- ActionParty：引入显式的主体状态token
- 结果：显著提升动作绑定准确性（MA: 0.779 vs 0.158）

**Spatial AGI的启示**：
1. **状态显式化**：为空间实体引入显式的状态表示
2. **可观测状态**：使内部状态可观察和可追踪
3. **状态-动作分离**：将状态表示与动作控制分离

#### 状态更新-渲染解耦

ActionParty实现了**状态更新和渲染的解耦**：

**游戏引擎类比**：
- 状态更新：根据动作更新内部状态
- 渲染：使用更新后的状态合成观测

**实现机制**：
- 交叉注意力：状态更新
- 自注意力：渲染
- 注意力掩码：控制信息流

**Spatial AGI的启示**：
1. **世界模型架构**：模拟游戏引擎的分离架构

## Q3: 自由问题

### 问题：为什么动作绑定在视频扩散模型中如此困难，以及ActionParty是如何从根本上解决这个问题的？

#### 1. 动作绑定困难的根本原因

##### 1.1 属性绑定问题的本质

**属性绑定（Attribute Binding）**是指将特定属性（如文本描述）与生成场景中的对应实体关联的挑战。这是生成模型中的一个基本问题，尤其是当场景中存在多个实体时。

**在视频生成中的特殊性**：
- **时间维度**：视频增加时间维度，使得绑定更加复杂
- **空间-时间绑定**：需要同时处理空间位置和时间一致性
- **动态实体**：实体在视频帧中移动和变化，增加绑定难度

**扩散模型的局限性**：
作者引用了先前的工作，表明：
> "当给定多个条件信号时，扩散模型经常忽略其中一些或合并多个信号，阻止它们实现多智能体仿真所需的每个主体控制。"

**具体表现**：
1. **信号忽略**：模型可能只关注部分条件信号
2. **信号合并**：多个信号被混合，失去明确的对应关系
3. **全局消歧**：模型必须在全局范围内消歧，而不是局部处理

##### 1.2 文本条件固有的歧义性

**文本描述的局限性**：

当使用文本描述来控制多个主体时，存在固有的歧义：

**示例**：
```
"红色三角形向右移动，蓝色正方形向左移动"
```

**歧义来源**：
1. **指代消歧**：哪个"红色三角形"？哪个"蓝色正方形"？
2. **空间消歧**：从哪个位置开始移动？
3. **时序消歧**：先移动哪个？同时移动？
4. **视觉消歧**：如果实体视觉相似，如何区分？

**扩散模型的处理方式**：
- 扩散模型将文本提示编码为全局条件
- 没有明确的机制将文本的不同部分与生成的不同区域关联
- 模型必须在隐式层面完成消歧，这对复杂场景来说过于困难

##### 1.3 像素空间的隐式表示

**隐式主体表示**：

传统视频扩散模型中，主体仅在像素空间中**隐式定义**：

**问题**：
- 除了视觉外观外，没有明确的主体表示
- 没有持久的身份标识跨越帧
- 无法显式地将动作锚定到特定主体

**后果**：
```
x_{t+1} ~ f_θ(x_{t+1} | x_{0:t}, a_{0:t})

模型必须：
1. 从x_{0:t}中隐式地识别主体
2. 理解a_{0:t}中的每个动作对应哪个主体
3. 将动作应用到正确的隐式主体表示
```

这是一个**极其困难**的任务，因为：
- 步骤1需要对象检测和跟踪
- 步骤2需要动作-主体关联推理
- 步骤3需要精确的局部控制和全局一致性

##### 1.4 缺乏持久状态

**状态持久性问题**：

传统模型缺乏**持久的隐式状态**来跨越时间步跟踪主体：

**自回归推理中的问题**：
- 每次生成新帧时，模型必须重新"找到"主体
- 没有持久的标识符来确保同一主体在不同帧中被正确识别
- 误差累积导致身份混淆或主体消失

**实验证据**：
基线方法在自回归步骤中快速退化：
```
Movement Accuracy (MA):
- 第一步：0.158（Text-Action基线）
- 后续步骤：接近0
```

这表明：
- 第一步可能通过视觉相似性勉强工作
- 后续步骤中身份丢失，动作绑定完全失败

#### 2. ActionParty的根本性解决方案

##### 2.1 显式状态token的引入

**核心创新**：

ActionParty引入了**显式的主体状态token**，从根本上改变了表示方式：

**新范式**：
```
x_{t+1}, z_{t+1} ~ f_θ(x_{t+1}, z_{t+1} | x_{0:t}, a_{0:t}, z_{0:t})
```

**状态token的特性**：
1. **持久性**：状态token跨越时间步存在
2. **唯一性**：每个主体有独立的状态token序列
3. **可观察性**：状态是显式的，可以被观察和操作

**为什么这是根本性的**：
- **消歧**：每个主体有唯一的标识符，不再需要隐式消歧
- **持久性**：身份跨越时间步保持，避免重新识别
- **可操作**：可以直接操作状态来控制主体

##### 2.2 坐标作为状态的充分性

**关键洞察**：

论文中发现：
> "对于大多数游戏环境，我们发现主体的空间位置足以区分它们，因为两个主体不能占据同一位置。"

**为什么坐标是充分的**：
1. **空间唯一性**：两个主体不能在同一时间占据同一位置
2. **空间区分性**：不同的坐标区分不同的主体
3. **可预测性**：位置随动作可预测地变化

**坐标编码**：
- 2D坐标：`(h, w)`
- 归一化：与VAE编码的视频潜在表示具有相似的统计特性
- 线性编码器/解码器：映射到模型内部维度

**最小表示原则**：
论文遵循最小表示原则：
- 坐标足够时，不添加额外信息
- 避免过度复杂化状态表示
- 提高模型的泛化能力

##### 2.3 生成式游戏引擎范式

**架构创新**：

ActionParty采用生成式游戏引擎范式，分离状态更新和渲染：

**传统视频生成**：
```
单一过程：直接从条件生成视频帧
```

**ActionParty的两阶段过程**：

**阶段1：状态更新（交叉注意力）**
```
使用动作更新状态：
z_{t+1}^i = Update(z_t^i, a_t^i)
```

**阶段2：渲染（自注意力）**
```
使用更新后的状态渲染视频帧：
x_{t+1} = Render(x_{0:t}, z_{t+1})
```

**为什么这是根本性的**：
1. **解耦关注点**：状态更新和渲染是独立的问题
2. **可解释性**：每个阶段有明确的目的
3. **模块化**：可以独立优化每个阶段
4. **模拟真实游戏引擎**：反映真实游戏引擎的工作方式

##### 2.4 注意力掩码的精确控制

**信息流控制**：

注意力掩码提供了对模型中信息流的**精确控制**：

**交叉注意力掩码（M_CA）**：
```
主体i的状态token z^i 仅允许关注其对应的动作嵌入 a^i
```

**为什么这是根本性的**：
1. **严格绑定**：强制执行动作-主体对应关系
2. **防止泄漏**：阻塞不同主体之间的信息混合
3. **可验证性**：可以从架构上验证动作绑定

**自注意力掩码（M_SA）**：
```
- 所有主体token → 视频token：允许（读取环境信息）
- 主体token → 主体token：阻止（避免状态混合）
- 视频token → 所有主体token：允许（使用所有主体状态）
```

**设计哲学**：
- 允许读取：主体需要环境信息来做出合理决策
- 阻止混合：保持主体的独立性
- 允许全局渲染：视频帧需要所有主体的状态

##### 2.5 RoPE偏置的空间锚定

**空间偏置机制**：

RoPE偏置解决了将主体状态token锚定到视频中的正确空间位置的问题：

**问题**：
自注意力掩码`M_SA`防止了主体混合，但没有显式地将视频中的主体与其状态token链接。

**解决方案**：
使用**3D Rotary Position Embeddings（RoPE）**来消除这种映射的歧义。

**工作原理**：
```
1. 视频token在位置 (h, w) 接收旋转 R(t, h, w)
2. 主体token使用前一位置 (h_{t-1}, w_{t-1}) 接收旋转 R(t, h_{t-1}, w_{t-1})
3. 相同坐标的token被偏置相互关注
```

**为什么这是根本性的**：
1. **空间局部性**：将全局消歧问题简化为局部精化
2. **对齐保证**：从架构上保证主体状态和视频位置的对齐
3. **误差容忍**：即使位置预测有小的误差，空间偏置仍然可以工作

**实验证据**：
移除RoPE偏置的消融研究：
```
Movement Accuracy (MA): 3.2%（vs 完整模型的87.2%）
```

这表明RoPE偏置对于任何动作绑定都是**必不可少**的。

##### 2.6 从隐式到显式的转变

**表示的范式转变**：

ActionParty代表了从隐式到显式表示的**范式转变**：

| 方面 | 隐式方法 | ActionParty（显式） |

| 主体表示 | 像素空间中的隐式 | 显式的状态token |

| 动作绑定 | 全局隐式消歧 | 通过掩码的精确绑定 |
| 空间关系 | 像素中隐式 | 显式的坐标 |
| 信息流 | 非结构化 | 通过掩码的精确控制 |

**为什么这种转变是根本性的**：
1. **可解释性**：显式表示更容易理解和调试
2. **可控性**：显式表示允许精确控制
3. **可扩展性**：显式表示更容易扩展到更多主体
4. **鲁棒性**：显式表示提供更好的鲁棒性

#### 3. 为什么传统方法失败的原因

##### 3.1 文本条件方法的局限性

**Zero-shot I2V基线**：

使用文本提示的零样本图像到视频方法：

**提示词格式**：
```
"player 1 starts at (col, row). player 2 starts at (col, row).
In frame N, player 1 moves forward. player 2 moves backwards."
```

**为什么失败**：
1. **全局条件**：文本被编码为全局条件，没有局部绑定
2. **隐式消歧**：模型必须隐式地将文本的不同部分与不同的主体关联
3. **视觉相似性**：如果主体在视觉上相似，文本描述无法区分它们
4. **时间累积**：随着时间的推移，小的误差累积导致完全失败

**实验证据**：
```
Movement Accuracy (MA): 接近0
Subject Preservation (SP): 接近0
```

##### 3.2 仅文本动作控制的失败

**Text-Action基线**：

使用相同的主干架构，但仅使用文本条件进行训练：

**为什么失败**：
1. **没有显式状态**：仍然依赖隐式主体表示
2. **没有持久标识符**：没有持久的身份标识符跨越帧
3. **没有空间锚定**：没有将动作锚定到特定的空间位置
4. **第一帧偏差**：在第一步可能工作（因为主体在初始位置），但快速退化

**实验证据**：
```
Movement Accuracy (MA):
- 第一步：0.158
- 后续步骤：接近0
```

##### 3.3 预训练AR基线的局限性

**Pretrained AR基线**：

在没有动作控制的情况下在游戏视频上预训练的自回归模型：

**为什么失败**：
1. **没有动作控制**：完全没有动作绑定机制
2. **随机行为**：生成随机视频，不遵循任何动作
3. **缺乏一致性**：没有主体状态的持久表示

**作用**：
作为一个**下界**，展示没有动作控制时的表现。

## 核心技术发现

### 1. 主体状态token的持久性效果

**发现**：
引入显式的主体状态token，为每个主体提供持久的隐式状态表示，可以跨越时间步持续存在。

**实验证据**：
- Movement Accuracy (MA)在自回归步骤中保持稳定
- Text-Action基线在后续步骤中快速退化到接近0
- ActionParty在多个rollout步中保持一致的性能

**原因分析**：
1. **持久身份**：每个主体有独立的token序列，提供持久的身份
2. **避免重新识别**：不需要每帧重新"找到"主体
3. **减少累积误差**：持久的标识符减少了身份混淆

**数值结果**：
```
Movement Accuracy (MA) across autoregressive steps:
- ActionParty: ~0.78（稳定）
- Text-Action: 0.158 → ~0（快速退化）
- Zero-shot I2V: ~0（完全失败）
```

### 2. RoPE偏置的空间锚定效果

**发现**：
使用3D Rotary Position Embeddings（RoPE）将主体状态token锚定到视频中的特定空间坐标，极大地简化了模型的任务。

**工作机制**：
- 视频token在位置(h, w)接收旋转R(t, h, w)
- 主体token使用前一位置(h_{t-1}, w_{t-1})接收旋转R(t, h_{t-1}, w_{t-1})
- 相同坐标的token被偏置相互关注

**关键优势**：
1. **从全局到局部**：将全局消歧简化为局部精化
2. **空间对齐**：从架构上保证主体状态和视频位置的对齐
3. **误差容忍**：即使位置预测有小的误差，空间偏置仍然可以工作

**实验证据**（消融研究）：
```
完整ActionParty：
- Movement Accuracy (MA): 87.2%
- Detection Rate (DR): 91.3%

移除RoPE偏置：
- Movement Accuracy (MA): 3.2%
- 模型完全无法执行任何动作绑定
```

**结论**：
RoPE偏置对于动作绑定是**必不可少**的，它是ActionParty成功的关键因素之一。

### 3. 注意力掩码的精确控制效果

**发现**：
通过注意力掩码精确控制模型中的信息流，可以实现严格的动作-主体绑定和防止主体之间的信息泄漏。

**两种掩码**：

**交叉注意力掩码（M_CA）**：
- 主体i的状态tokenz^i仅允许关注其对应的动作嵌入a^i
- 阻塞所有不匹配动作和主体token之间的通信
- 保留预训练模型的容量（文本嵌入c仅允许关注视频tokenx）

**自注意力掩码（M_SA）**：
- 所有主体token → 视频token：允许（读取环境信息）
- 主体token → 主体token：阻止（避免状态混合）
- 视频token → 所有主体token：允许（使用所有主体状态）

**实验证据**（消融研究）：

**移除自注意力掩码M_SA**：
```
Movement Accuracy (MA): 58%（vs 87.2%完整模型）
原因：主体token被允许相互关注，导致信息泄漏
```

**移除交叉注意力掩码M_CA**：
```
Movement Accuracy (MA): 5.2%（vs 87.2%完整模型）
原因：动作无法正确绑定到主体状态token
```

**结论**：
两种掩码都是必不可少的，它们协同工作以实现精确的动作控制。

### 4. 状态更新-渲染分离的架构效果

**发现**：
模仿游戏引擎的架构，将单帧生成分解为状态更新和渲染两个阶段，显著提升了可控性和可解释性。

**两阶段过程**：

**阶段1：状态更新（交叉注意力）**
```
目标：根据特定主体的动作更新其状态
实现：通过交叉注意力层处理动作输入
机制：使用注意力掩码强制执行严格的主体-动作绑定
```

**阶段2：渲染（自注意力）**
```
目标：使用更新后的主体状态合成视频帧
实现：通过自注意力层进行视频帧渲染
机制：使用RoPE偏置将主体状态锚定到正确位置
```

**优势**：
1. **解耦关注点**：状态更新和渲染是独立的问题
2. **可解释性**：每个阶段有明确的目的
3. **模块化**：可以独立优化每个阶段
4. **模拟真实游戏引擎**：反映真实游戏引擎的工作方式

**实验证据**：
完整的ActionParty模型显著优于所有基线：
```
Movement Accuracy (MA): 77.9% vs 15.8%（最佳基线）
Subject Preservation (SP): 90.3% vs 66.8%（最佳基线）
Detection Rate (DR): 88.6% vs 基线
```

### 5. 联合建模视频和状态的效果

**发现**：
联合建模视频帧和主体状态，而不是分离建模，提供了显著的性能提升。

**目标**：
```
x_{t+1}, z_{t+1} ~ f_θ(x_{t+1}, z_{t+1} | x_{0:t}, a_{0:t}, z_{0:t})
```

**优势**：
1. **相互增强**：视频生成和状态预测相互增强
2. **一致性**：确保视频和状态的一致性
3. **数据效率**：联合学习比分离学习更数据高效
4. **端到端优化**：可以端到端优化整个系统

**架构实现**：
- 扩展标准视频DiT架构以联合去噪x和z
- 类似MMDiT（SD3）的架构
- 将扁平化的视频token和主体状态token沿序列维度连接

**实验证据**：
完整的联合建模ActionParty显著优于所有基线：
- 在所有评估指标上都表现出色
- 特别是在动作绑定准确性上有显著提升

### 6. 统一动作空间的泛化效果

**发现**：
训练一个模型使用统一的动作空间在46个不同的游戏环境中泛化，展示了强大的泛化能力。

**动作空间**：
- 25个不同的离散动作
- 7个基础动作：Idle、Move（4个方向）、Turn（2个方向）、Interact
- 动作是相对的，取决于主体的朝向

**泛化挑战**：
- 46个不同的2D游戏
- 不同的环境和静态对象
- 有些角色可能看起来相同
- 不同的游戏使用不同的动作子集

**实验证据**：
ActionParty在所有46个游戏中都表现出色：
```
Movement Accuracy (MA): 77.9%（所有游戏平均）
Effect Accuracy (EA): 在所有动作类型上都表现出色
Subject Preservation (SP): 90.3%
Detection Rate (DR): 88.6%
```

**细粒度分析**（按主体数量分类）：
- Sparse (2-3个主体)：17个游戏
- Dense (4-5个主体)：24个游戏
- Crowded (6-7个主体)：5个游戏

ActionParty在所有类别中都保持一致的动过跟随和视觉质量。

### 7. 上下文依赖动作的处理能力

**发现**：
ActionParty能够有效处理上下文相关的"Interact"动作，其效果取决于当前状态和环境。

**Interact动作的挑战**：
- 动作效果取决于主体当前状态（位置、朝向）
- 动作效果取决于环境（如是否有墙壁）
- 不同的游戏有不同的"Interact"效果：
  - 激活主体前方的瓦片
  - 发射光束
  - 与物体交互

**评估方法**：

- 提取以真实玩家位置为中心的3×3瓦片补丁
- 使用SSIM评估与前一帧的不相似度
- 阈值：补丁SSIM ≥ 0.85以检测执行的动作

**实验证据**：
ActionParty在所有动作类型上都表现出色，特别是"Interact"动作：
```
Effect Accuracy (EA):
- ActionParty: 在所有动作类型上都达到最高准确率
- 相比基线：Interact动作的成功率超过两倍
```

**原因分析**：
1. **显式状态**：状态token捕获主体当前状态
2. **空间锚定**：RoPE偏置确保动作应用到正确的空间位置
3. **联合建模**：联合建模视频和状态确保一致性

### 8. 多主体同时控制的可扩展性

## 个人思考

### 最有趣的发现

#### 1. 坐标作为状态的充分性

**发现**：
对于大多数游戏环境，主体的**空间位置足以区分它们**，因为两个主体不能占据同一位置。

**为什么有趣**：
1. **简洁性**：使用如此简单的表示（2D坐标）就能解决复杂的动作绑定问题
2. **违反直觉**：我们可能认为需要更复杂的状态表示（如外观、朝向等）
3. **有效性**：实验证明这种简单表示在实际工作中非常有效

**深层思考**：
这揭示了空间信息在多主体系统中的**根本重要性**。即使主体在视觉上完全相同，只要它们在不同的空间位置，就可以通过位置来区分它们。

**对Spatial AGI的启示**：
在构建空间智能系统时，应该优先考虑空间信息，而不是过度复杂化状态表示。简单的空间表示往往比复杂的隐式表示更有效。

#### 2. 动作的相对性

**发现**：
Melting Pot数据集中的动作是**相对于主体朝向**的，而不是绝对方向。

**为什么有趣**：
1. **增加复杂性**：相对动作比绝对动作更难学习，因为模型必须理解当前朝向
2. **真实世界性**：这与真实世界中的机器人控制更相似（前进意味着在朝向的方向上移动）
3. **视觉推理需求**：模型必须从视觉观察中推断朝向，而不是显式给出

**深层思考**：
这表明Spatial AGI系统需要能够从视觉观察中推断空间关系，而不是依赖显式的空间指令。这是一个更符合真实世界的设置。

**对Spatial AGI的启示**：
Spatial AGI系统应该具备：
1. **视觉-空间推理**：从视觉观察中提取空间关系
2. **相对动作理解**：理解动作如何相对于当前状态改变空间位置
3. **上下文依赖性**：理解动作的效果取决于当前空间状态

#### 3. 动作绑定在简单环境中的失败

**发现**：
即使是最先进的视频生成器（如Veo 3）也无法在简单的两个形状环境中正确执行基本的多主体动作指令。

**为什么有趣**：
1. **简单性**：这是一个非常简单的环境（两个形状在实心背景上）
2. **明显失败**：失败非常明显和可观察
3. **普遍性**：这表明问题不是特定于某个模型，而是扩散模型的普遍限制

**深层思考**：
这揭示了扩散模型在属性绑定方面的**根本性局限**。即使对于如此简单的场景，模型也无法正确地将动作绑定到正确的主体。这说明问题不在于场景的复杂性，而在于模型架构本身。

**对Spatial AGI的启示**：
在构建Spatial AGI系统时，不能依赖现有的生成模型来处理多主体场景。我们需要设计专门的架构（如ActionParty）来解决动作绑定问题。

### 最意外的结果

#### 1. Text-Action基线的快速退化

**结果**：
Text-Action基线在第一步之后**快速退化到接近0**的Movement Accuracy。

**为什么意外**：
1. **初始成功**：在第一步，Text-Action基线可能达到可接受的结果（MA: 0.158）
2. **快速失败**：但在后续步骤中，性能快速退化到接近0
3. **完全失效**：在多个rollout步中，动作绑定完全失效

**原因分析**：
1. **第一帧偏差**：在第一步，主体仍在初始位置，模型可能通过视觉相似性勉强工作
2. **缺乏持久标识符**：没有持久的身份标识符，模型无法在后续步骤中正确识别主体
3. **误差累积**：小的误差快速累积，导致完全的身份混淆

**深层思考**：
这表明**持久的身份标识符**对于多主体控制是**必不可少的**。即使模型能在单步场景中工作，没有持久的标识符，也无法在长时序场景中工作。

**对Spatial AGI的启示**：
Spatial AGI系统必须为每个空间实体提供持久的标识符，否则在长时序推理中会失败。

#### 2. RoPE偏置的绝对必要性

**结果**：
移除RoPE偏置后，Movement Accuracy从87.2%**下降到3.2%**。

**为什么意外**：
1. **幅度**：性能下降如此剧烈（从87.2%到3.2%）
2. **完全失效**：模型几乎完全无法执行任何动作绑定
3. **必要性**：这表明RoPE偏置不是锦上添花，而是绝对必要

**原因分析**：
没有RoPE偏置，主体状态token无法与视频中的正确空间位置对齐，导致：
1. 全局消歧问题：模型必须在全局范围内消歧，而不是局部处理
2. 空间错位：状态token可能与错误的空间区域关联
3. 动作混淆：动作可能应用到错误的空间位置

**深层思考**：
这表明**空间锚定**是动作绑定的**核心机制**。没有空间锚定，即使有其他组件（状态token、注意力掩码），也无法实现正确的动作绑定。

**对Spatial AGI的启示**：
在构建Spatial AGI系统时，空间锚定机制是必不可少的。我们需要设计机制将动作锚定到正确的空间位置。

#### 3. 自注意力掩码的重要性

**结果**：
移除自注意力掩码后，Movement Accuracy从87.2%**下降到58%**。

**为什么意外**：
1. **幅度**：性能下降显著（从87.2%到58%）
2. **仍能工作**：模型仍然能够执行一定的动作绑定（vs 移除RoPE偏置的3.2%）
3. **信息泄漏**：下降的主要原因是主体之间的信息泄漏

**原因分析**：
移除自注意力掩码后：
1. 主体token可以相互关注
2. 不同主体的状态信息开始混合
3. 导致主体混淆和动作绑定错误

**深层思考**：
这表明**防止主体之间的信息泄漏**对于保持主体独立性是重要的。虽然不如RoPE偏置那么关键，但仍然是重要组件。

**对Spatial AGI的启示**：
在构建Spatial AGI系统时，需要设计机制防止不同实体之间的信息泄漏，以保持实体的独立性。

### 最有价值的启发

#### 1. 显式表示的价值

**启发**：
显式的状态表示比隐式的像素级表示**更有效、更可控、更可解释**。

**价值**：
1. **有效性**：ActionParty显著优于所有基于隐式表示的基线
2. **可控性**：可以直接操作显式状态来控制主体
3. **可解释性**：显式状态更容易理解和调试
4. **可验证性**：可以从架构上验证属性绑定

**对Spatial AGI的启示**：
在构建Spatial AGI系统时，应该优先考虑**显式的空间表示**：
1. **实体状态显式化**：为每个空间实体引入显式的状态表示
2. **可观测状态**：使内部状态可观察和可追踪
3. **分离关注点**：将状态表示与观测生成分离

#### 2. 空间局部性的利用

**启发**：
利用**空间局部性**可以将复杂的全局问题简化为局部问题。

**价值**：
1. **简化问题**：RoPE偏置将全局消歧简化为局部精化
2. **误差容忍**：即使有小的位置误差，空间偏置仍然可以工作
3. **计算效率**：局部处理比全局处理更高效

**对Spatial AGI的启示**：
在构建Spatial AGI系统时，应该**利用空间局部性**：
1. **局部决策**：在局部空间内做出决策
2. **问题分解**：将全局空间问题分解为局部子问题
3. **局部注意力**：引导系统关注相关的局部空间区域

#### 3. 架构解耦的重要性

**启发**：
将复杂系统**解耦**为更简单的模块，可以提高可控性、可解释性和可维护性。

**价值**：
1. **可控性**：每个模块可以独立控制
2. **可解释性**：每个模块有明确的目的
3. **模块化**：可以独立优化每个模块
4. **可维护性**：模块化系统更容易维护和扩展

**对Spatial AGI的启示**：
在构建Spatial AGI系统时，应该考虑**架构解耦**：
1. **状态更新-渲染分离**：分离状态推理和观测生成
2. **模块化设计**：设计可独立优化的模块
3. **清晰接口**：定义模块之间的清晰接口

#### 4. 联合建模的价值

**启发**：
**联合建模**多个相关变量比分离建模更有效。

**价值**：
1. **相互增强**：不同任务的预测相互增强
2. **一致性**：确保不同预测之间的一致性
3. **数据效率**：联合学习比分离学习更数据高效
4. **端到端优化**：可以端到端优化整个系统

**对Spatial AGI的启示**：
在构建Spatial AGI系统时，应该考虑**联合建模**：
1. **多任务学习**：联合学习多个相关任务
2. **一致性保证**：确保不同预测之间的一致性
3. **端到端优化**：优化整个空间智能系统

#### 5. 注意力掩码的精确控制

**启发**：
使用**注意力掩码**可以实现信息流的精确控制，确保架构级别的正确行为。

**价值**：
1. **精确控制**：可以精确控制模型中的信息流
2. **架构约束**：通过架构约束确保正确的行为
3. **可验证性**：可以从架构上验证绑定和约束

**对Spatial AGI的启示**：
在构建Spatial AGI系统时，应该考虑使用**注意力掩码**或其他机制来实现：
1. **信息流控制**：精确控制模型中的信息流

## 总结

### 论文核心

ActionParty解决了视频扩散模型在**多主体场景中的动作绑定问题**。当场景中存在多个可控制主体时，模型必须能够正确地将每个控制信号与其对应的主体关联。然而，现有模型面临一个根本性挑战：除了视觉外观外，没有明确的主体表示来锚定动作。

### 主要贡献

1. **提出ActionParty框架**：一个新颖的自回归视频生成器，用于生成游戏模拟。联合建模视频帧和每个主体的状态，并引入注意力掩码以强制执行动作-主体对应关系。

2. **引入主体状态token**：显式的潜在变量，持久捕获场景中每个主体的状态。对于大多数游戏环境，2D坐标足以区分主体。

3. **设计生成式游戏引擎**：将单帧生成分解为状态更新和渲染两个阶段。交叉注意力处理状态更新，自注意力处理渲染，注意力掩码控制信息流。

4. **实现RoPE偏置机制**：使用3D Rotary Position Embeddings将主体状态锚定到视频中的特定空间坐标，将全局消歧简化为局部精化。

5. **首次展示多主体世界模型**：在46个不同环境中同时控制多达7个主体，在动作跟随和主体一致性方面实现卓越性能。

### 实验结果

**定量评估**：
- Movement Accuracy (MA): 77.9%（vs 15.8%最佳基线）
- Subject Preservation (SP): 90.3%（vs 66.8%最佳基线）
- Detection Rate (DR): 88.6%
- Effect Accuracy (EA): 在所有动作类型上都最高，"Interact"动作成功率超过基线两倍

**自回归稳定性**：
- ActionParty在多个rollout步中保持稳定（MA: ~0.78）
- 基线在后续步骤中快速退化到接近0

**泛化能力**：
- 46个不同游戏
- 2-7个主体的场景
- 统一的动作空间

### 消融研究

**关键发现**：
- RoPE偏置对于动作绑定是绝对必要的（移除后MA从87.2%降至3.2%）
- 交叉注意力掩码M_CA也很关键（移除后MA降至5.2%）
- 自注意力掩码M_SA提供重要改进（移除后MA降至58%）

### 计算效率

- 对于T=5的7玩家场景，仅增加6%的开销（40个额外token）
- 相比为每个主体生成多个视角的方法显著更高效

### 对Spatial AGI的意义

1. **直接贡献**：
   - 多主体空间表示框架
   - 动作-空间绑定机制
   - 空间局部性利用

2. **技术启发**：
   - 从隐式到显式的表示转变
   - 状态更新-渲染解耦
   - 联合建模的价值
   - 注意力掩码的精确控制

3. **应用场景**：
   - 机器人多智能体系统
   - AR/VR多用户环境
   - 虚拟环境仿真
   - 自动驾驶多车辆仿真
   - 无人机编队控制
   - 多智能体强化学习

### 局限性

1. **2D设置**：目前仅在2D游戏设置中测试，未来工作可扩展到3D场景
2. **计算效率**：模型尚未完全实时，但可以通过蒸馏和diffusion forcing等技术优化
3. **位置误差**：预测的位置zt可能不完全与主体对齐，但我们的平滑位置偏置允许动作仍然绑定到正确的主体
4. **主体消失**：一些主体可能消失，阻止与场景的进一步交互

### 未来方向

1. **3D扩展**：扩展到3D场景，其中主体可能部分可见
2. **实时优化**：通过蒸馏和diffusion forcing等技术优化模型以实现实时性能
3. **更复杂的动作空间**：支持更复杂的动作，如连续控制
4. **更多实体**：扩展到更多的实体类型和数量
5. **跨领域应用**：应用到其他多主体领域，如机器人、自动驾驶等

- Multiverse、Solaris：为3D世界中的每个主体生成对齐视图
- MultiGen：预测显式游戏状态（包括小地图和玩家状态）用于对齐多玩家视图
- 局限：单独的智能体建模使视频token数量与智能体数量线性扩展，可能解释了为什么它们只在单个游戏的两玩家设置中测试

**对比ActionParty**：
- 生成包含所有智能体的单个视频，需要动作绑定
- 扩展到多达7个智能体
- 单模型在46个游戏上泛化

### 视频扩散模型中的运动控制

**主要方向**：

**1. 对象轨迹控制**：
- 提供辅助控制信号，如对象掩码和沿轨迹的边界框
- 代表性工作：DragNUWA, DragAnything, Tora, SG-I2V, Boximator, MotionPrompting

**2. 运动转移**：
- 将参考视频的运动转移到新合成的视频
- 代表性工作：SMM, MOFT, DiTFlow, MotionDirector, VMC, MatchDiffusion, RoPECraft

**3. 人类运动生成**：
- 从文本描述生成逼真的运动序列或姿势
- 代表性工作：Human Motion Diffusion Model, MotionDiffuse, MotionGPT

**与ActionParty的对比**：
- 主要为单个主体生成运动
- 在结构化姿势空间中操作
- 游戏设置涉及比纯运动更抽象的动作（如与物品交互、发射光束）
- 这些动作取决于主体的当前状态（如当前朝向）

### 生成模型中的属性绑定

**定义**：
属性绑定是指将特定属性（如文本描述）与生成场景中的对应实体关联的挑战。

**主要方向**：

**1. 组合生成**：
- 将外观描述或空间关系绑定到不同的主体，而不混合属性
- 使用空间掩码机制实现
- 代表性工作：Improving Compositional Attribute Binding, Attend-and-Excite, Compositional Visual Generation

**2. 场景图引导生成**：
- 条件化实体、属性和空间关系的结构化地图
- 代表性工作：SceneGenie, GraphDreamer, Controllable Scene Generation

**3. 视频中的时空绑定**：
- 更复杂的问题，尚未解决
- 尤其是当视频中有多个实体时
- 代表性工作：MinT, LLMGroundedDM, VideoDirectorGPT

**与ActionParty的对比**：
- ActionParty通过显式状态token和注意力掩码解决多主体动作绑定
- 提供架构级别的绑定保证
- 支持长时序的自回归推理
