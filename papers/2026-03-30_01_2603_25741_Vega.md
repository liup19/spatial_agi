## 摘要

### 核心问题

现有的自动驾驶方法在处理自然语言指令方面存在显著不足。大多数现有的视觉-语言-动作（VLA）模型仅将语言模态用于场景描述或推理，缺乏灵活性来遵循多样化的用户指令以实现个性化驾驶。

### 核心贡献

1. **大规模指令驾驶数据集（InstructScene）**：
   - 包含约100,000个场景
   - 每个场景都标注了多样化的驾驶指令和相应的轨迹
   - 基于NAVSIM构建

2. **统一的视觉-语言-世界-动作模型（Vega）**：
   - 基于指令的生成和规划
   - 采用自回归范式处理视觉输入和语言指令
   - 采用扩散范式生成未来预测和轨迹
   - 使用联合注意力实现模态间交互
   - 使用单独的投影层实现不同模态的独立能力

3. **性能表现**：
   - 在规划性能方面实现优越表现
   - 展现出强大的指令遵循能力
   - 能够生成高保真且符合指令的未来图像和合理的轨迹

### 方法论

- **世界建模与规划的结合**：通过联合学习基于指令的动作规划和未来图像生成，模型被迫学习指令、动作和视觉结果之间的因果关系
- **混合自回归-扩散Transformer架构**：
  - 自回归：用于视觉和指令理解
  - 扩散：用于图像和动作生成
  - 联合注意力：跨模态交互
  - Mixture-of-Transformers（MoT）设计：解耦不同模态相关参数

## 引言

### 背景

#### 视觉中心自动驾驶的优势

- 经济优势
- 可扩展性好
- 避免昂贵的3D标注依赖

#### 传统模块化流水线

```
感知（Perception）→ 预测（Prediction）→ 规划（Planning）
```

**问题**：严重依赖昂贵的3D标注，在实际应用中面临限制

#### VLA模型的兴起

- 利用大语言模型的丰富世界知识
- 将视觉输入映射到驾驶动作
- 在各种驾驶场景中显示出显著的泛化能力

### 现有VLA模型的局限性

1. **有限的指令遵循能力**：
   - 仅使用语言进行场景描述或决策推理
   - 缺乏灵活的指令遵循能力
   - 训练为模仿平均专家策略
   - 受限于简单的导航命令集合（如"左转"、"直行"）

2. **无法处理开放式自然语言指令**：
   - 用户可能有个性化需求
   - 示例："超越前车以赶上下一个绿灯"
   - 现有模型无法理解此类指令

### 本文动机

从模仿驾驶转向指令驱动的驾驶：
- 通用驾驶代理应不仅自主导航
- 还应理解并执行多样化的、用户指定的自然语言指令
- 实现更加智能和个性化的驾驶系统

### 核心挑战

直接在包含丰富指令的驾驶数据集上训练VLA模型存在困难：
- **信息差距**：高维视觉-指令输入与低维动作预测之间存在巨大信息差距
- **泛化困难**：难以在复杂动态环境中学习从高级指令到低级动作的可泛化映射

### 解决方案概览

1. **构建大规模数据集**：InstructScene
2. **统一生成与规划框架**：
   - 联合执行基于指令的生成和规划
   - 提供密集和像素级的监督信号
   - 强制模型学习指令、动作和视觉预测之间的因果关系
3. **混合架构**：自回归-扩散Transformer

## 相关工作

### 1. VLM和VLA在自动驾驶中的应用

#### 早期VLM应用

- **用途**：高级驾驶场景理解和推理
- **局限**：无法输出可行驶轨迹

#### VLA的发展

**第一阶段**：直接预测文本路标点
- **问题**：LLM在精确数值推理方面的固有局限性

**第二阶段**：集成规划模块实现端到端轨迹预测
- **常见规划方法**：
  - 离散路标点的自回归预测
  - 基于扩散的轨迹生成
  - 通过MLP头的直接回归

**问题**：稀疏的动作监督，依赖辅助理解和推理任务

**Vega的创新**：
- 采用世界建模提供密集信号增强基于指令的规划

### 2. 自动驾驶的世界模型

#### 世界模型定义

根据过去的观察和当前动作预测未来状态的生成模型

#### 应用分类

**图像方法**：
- 利用强大的生成架构合成高保真驾驶视频
- 主要用途：数据生成和场景模拟

**占用方法**：
- 在3D占用空间中建模场景演变
- 增强场景理解和规划
- 依赖密集3D标签，限制可扩展性

**VLA方法**：
- Doe-1：首次提出统一场景理解、预测和规划的闭环驾驶模型
- DriveVLA-W0：将世界建模集成到VLA框架中
- **局限**：无法执行基于指令的预测和规划

**Vega的优势**：
- 实现基于指令的预测和规划能力
- 可以根据灵活的语言指令预测相应的未来场景和驾驶轨迹

### 3. 统一视觉理解和生成

#### 方法分类

**1. 量化自回归（AR）模型**：
- 将图像量化为离散token
- 在原生自回归框架内实现生成
- **问题**：视觉质量通常落后于基于扩散的方法

**2. 外部扩散器方法**：
- 将VLM与外部扩散模型配对
- VLM通过生成少量潜在token提供高级理解
- **问题**：理解和生成之间的狭窄接口限制信息流

**3. 集成Transformer模型**：
- 将自回归和扩散机制合并到单个transformer中
- 实现强大理解和生成能力的深度集成
- **Vega的选择**：采用集成transformer实现基于指令的联合视觉生成和动作规划

## 核心方法

### 3.1 从模仿驾驶到指令驾驶

#### 传统自动驾驶模型

**输入**：
- 过去T帧图像：[I_{t-T}, ..., I_t]
- 过去T帧动作：[A_{t-T}, ..., A_{t-1}]

**输出**：
- 当前动作：A_t

**公式**：
```
A_t = M([I_{t-T}, ..., I_t], [A_{t-T}, ..., A_{t-1}])
```

#### 模块化流水线

```
1. 感知模块 P_er：
   从观察中提取场景表示 z

2. 预测模块 P_re：
   基于z预测代理的未来运动 v

3. 规划模块 P_lan：
   使用z、v和历史动作规划当前动作 A_t
```

**问题**：严重依赖昂贵的高质量3D标注

#### 现有VLA模型

**输入**：过去观察 + 历史动作

**输出**：
- 场景的文本描述 D_t
- 当前ego车辆动作 A_t

**公式**：
```
A_t, D_t = W([I_{t-T}, ..., I_t], [A_{t-T}, ..., A_{t-1}])
```

**局限**：
- 强大的泛化能力
- 但在灵活指令遵循方面存在不足
- 训练为模仿平均专家策略或处理简单导航命令的封闭集合
- 无法处理开放式自然语言指令

#### 指令驱动驾驶模型

**输入**：
- 观察：[I_{t-T}, ..., I_t]
- 历史动作：[A_{t-T}, ..., A_{t-1}]
- 当前用户指令：L_t

**输出**：
- 当前动作：A_t

**公式**：
```
A_t = V([I_{t-T}, ..., I_t], [A_{t-T}, ..., A_{t-1}], L_t)
```

#### InstructScene数据集构建

**规模**：约100,000个指令标注场景
**基础**：NAVSIM

**生成方法**：
1. **VLM自动生成**：
   - 输入：未来观察 [I_{t+1}, ..., I_{t+N}] 和动作 [A_{t+1}, ..., A_{t+N}]
   - 输出：描述当前ego车辆驾驶意图的高级指令 L_t

2. **基于规则的补充**：
   - 使用速度、加速度和转向率阈值分类场景
   - 转换为自然语言
   - 虽然缺乏多样性，但提供精确的ego运动提示
   - 作为VLM的辅助提示

**结果数据集**：
```
D = {<I_t, L_t, a_t>}_{t=1}^{T_max}
```

训练模型后，为其配备指令遵循驾驶能力

### 3.2 统一生成和规划

#### 问题诊断

直接在包含丰富指令的驾驶数据集上训练VLA模型面临困难：
- 难以生成可行的轨迹
- 难以准确遵循指令

**根本原因**：稀疏动作监督

#### 解决方案：视觉-语言-世界-动作模型

**核心洞察**：
- 未来图像生成提供密集、像素级的监督信号
- 帮助模型学习世界的底层动态
- 通过联合建模生成和规划，模型被迫学习指令、动作和视觉结果之间的因果关系
- 对于基于指令的规划至关重要

#### 框架公式

**生成模型**：在图像、指令和动作的三元组上训练

**驾驶的基本因果链**：
```
代理感知世界 I_t
→ 接收指令 L_t
→ 决定动作 A_t
→ 观察下一个结果 I_{t+1}
```

**每步操作**：
1. 接收当前观察 I_t 和指令 L_t
2. 接收历史观察 [I_{t-T}, ..., I_{t-1}]
3. 联合预测：
   - 要执行的动作 A_t
   - 产生的下一步 I_{t+1}

**因果注意力建模**：
- 确保模型学习从指令到动作再到视觉结果的正确推理路径
- 为解决监督差距提供坚实基础

### 3.3 联合自回归-扩散架构

#### 统一生成和规划的需求

模型需要具备的能力：
1. 显著的视觉-文本理解
2. 视觉生成
3. 动作规划
4. 将这些能力集成以解决复杂驾驶场景

#### 现有方法的不足

**1. 自回归视觉生成模型**：
- 使用离散视觉tokenizer
- 难以在图像质量上匹敌扩散模型
- 由于顺序生成管道，延迟高

**2. LLM结合外部扩散器**：
- 由于从LLM传递到生成模块的潜在token数量有限
- 受到信息瓶颈限制

#### 集成Transformer架构

**选择理由**：
- 将自回归VLM和扩散transformer融合到单个模型中
- 生成模块可以与理解模块交互而不会丢失信息
- 实现统一的理解和生成能力

#### 统一范式

**步骤1：编码多模态输入**
- 文本：使用Qwen2.5 tokenizer标记自然语言输入 L_t
- 视觉：
  - 仅使用前视相机图像作为视觉观察
  - 通过VAE编码器编码为潜在变量 F_t^V
  - 使用SigLIP2 ViT编码器编码输入图像
  - 将潜在变量附加到对应图像的VAE潜在变量
- 动作：
  - 将2D绝对轨迹 traj = [(x, y, θ), ...] 转换为连续步之间的相对移动
  - A = (Δx, Δy, Δθ)
  - 使来自不同步骤的动作共享分布并易于归一化
  - 通过线性头将归一化的相对动作序列投影到模型的潜在维度

**步骤2：构建输入序列**

多模态段以交错方式组合：

```
序列顺序：
1. 历史图像 [I_{t-T}, ..., I_t] 和动作 [A_{t-T}, ..., A_{t-1}]
2. 自然语言指令 L_t
3. 根据任务：
   - 动作规划：添加噪声目标动作 A_t^{noisy}
   - 视觉生成：先添加真实当前动作 A_t，然后添加噪声未来图像 I_{t+K}^{noisy}
```

**注意力掩码**：
- 序列 S = [I_0, L_0, A_0, ..., I_n, L_n, A_n]
- 严格因果性：设置为块下三角矩阵
- 每个块（代表图像、动作或指令）只能关注之前的块

**文本块**：
- 严格下三角掩码进行因果自注意力
- 为文本token分配连续的RoPE索引

**图像或动作块**：
- 采用全注意力掩码
- 所有token共享相同的RoPE索引
- 使用正弦位置编码来编码相对位置

**推理阶段**：
- 模型按顺序去噪动作和未来图像
- 未来图像预测以完全去噪动作为条件

**训练阶段**：
- 两个任务联合优化以提高训练效率
- 直接连接噪声动作和图像输入会导致后token关注噪声先验潜在变量
- 与推理不匹配，降低训练效果

**解决方案**：
- 复制每个既作为预测目标又作为后续预测条件的潜在变量
  - 添加噪声到第一个副本 F_t^{noisy} 用于去噪监督
  - 保持第二个副本 F_t^{clean} 作为条件输入
- 从所有后续token掩码 F_t^{noisy}
- 确保它们只关注干净潜在变量
- 允许在单个自回归序列中高效训练多个扩散过程

#### 集成Transformer设计

**目标**：增强集成transformer的性能

**策略**：解耦负责每个能力的模块和权重，使它们可以单独优化

**Mixture-of-Transformers（MoT）架构**：
- 与Mixture of Expert（MoE）技术不同（仅在FFN使用单独权重）
- 复制transformer的所有可训练参数，包括注意力和FFN层，用于每个模块
- 优势：
  - 收敛更快
  - 维持更高的模型容量

**模块配置**：

1. **理解transformer**：
   - 处理视觉和文本理解token
   - 基于Qwen2.5 LLM
   - 隐藏大小：3584
   - 深度：28层

2. **生成transformer**：
   - 处理图像生成token
   - 相同的设计
   - 两个transformer的权重从Bagel-7B初始化

3. **动作模块**：
   - 由于动作空间维度相对较低
   - 将动作模块的隐藏大小减少到256
   - 降低动作相关计算而不显著降低模型性能

**前向过程**：
1. 交错多模态序列被分割为段
2. 在每个注意力和FFN层传递到各自模块
3. 重新组装序列作为整体处理以计算全局因果注意力
4. 从输出序列中提取用于图像生成和动作规划的token以进行最终预测

### 3.4 训练和推理

#### 单阶段训练范式

**覆盖范围**：动作规划和世界建模

**动作规划**：
- **目标**：预测动作计划 A_t^{(N)} = [A_t, ..., A_{t+N-1}]
- **条件**：
  - 过去观察 I_t^{(-T)} = [I_{t-T}, ..., I_t]
  - 当前驾驶指令 L_t

**世界建模**：
- **目标**：预测未来图像观察 I_{t+K}
- **条件**：
  - 过去图像 I_t^{(-T)}
  - 当前驾驶指令 L_t
  - 动作计划 A_t^{(N)}

#### 损失函数

**动作损失**：归一化相对动作 A 的 MSE
```
L_A = E_{A_t^{(N)}, ε, m}[||ε - ε̂(A_t^{(N)}, ε, m, I_t^{(-T)}, L_t)||^2]
```

其中：
- ε ~ N(0, I) 是采样高斯噪声
- m 是随机时间步

**图像损失**：VAE潜在变量 F^V 的 MSE
```
L_V = E_{F_{t+K}^V, ε, n}[||ε - ε̂(F_{t+K}^V, ε, n, I_t^{(-T)}, L_t, A_t^{(N)})||^2]
```

其中：
- ε ~ N(0, I) 是采样高斯噪声
- n 是随机时间步

#### 分类器自由引导（CFG）

**训练阶段**：
- 随机删除文本、ViT、干净VAE和干净动作token
- 属于不同图像或动作的相同模态token被联合删除或保留

**推理阶段**：
- 使用分类器自由引导扩散生成动作
- 同时启用图像引导和文本引导
- 主要关注动作规划任务
- 模型保留训练阶段的图像生成能力

**联合目标**：
```
L_pretrain = λ_A · L_A + λ_V · L_V
```

- 允许模型与规划能力同时学习世界知识
- 典型设置：λ_A = λ_V = 1.0

## 实验结果

### 4.1 数据集和基准

#### NAVSIM v1

- **过滤**：过滤OpenScene移除近乎平凡和错误的场景
- **训练集规模**：缩减至85k
- **评估方法**：
  - 以10Hz运行非反应性模拟4秒
  - 用以下指标评分驾驶代理：
    - 无过错碰撞（NC）
    - 可行驶区域合规性（DAC）
    - 碰撞时间（TTC）
    - 舒适度（Comf.）
    - Ego进度（EP）
  - 聚合为预测驱动模型评分（PDMS）
- **使用**：训练split用于微调，测试split用于评估

#### NAVSIM v2

- **改进**：通过启用反应性交通提高模拟真实性
- **评估指标**：扩展预测驱动模型评分（EPDMS）
- **新增指标**：
  - 驾驶方向合规性（DDC）
  - 交通灯合规性（TLC）
  - 车道保持（LK）
  - 历史舒适度（HC）
  - 扩展舒适度（EC）

### 4.2 实现细节

#### 指令标注

**完全自动化的两阶段标注流水线**

**选择模型**：Qwen2.5-VL-72B-Instruct
- 强大的视觉理解能力

**场景输入**：
- 前视相机捕获的14连续帧
- 频率：2Hz
- 分辨率：(1920, 1080)
- 前4帧：过去和当前观察
- 后10帧：未来观察（推理阶段不会提供给驾驶代理）

**阶段一：场景理解**

输入要求1：
- 描述前4帧中的场景

## 核心技术发现

### 发现1：密集视觉监督的威力

**传统方法**：
- 仅使用稀疏动作标签（轨迹点）
- 监督信号密度低
- 难以弥合高维视觉输入和低维动作输出之间的差距

**Vega的创新**：
- 联合训练动作规划和未来图像生成
- 未来图像提供像素级密集监督
- 强制模型学习环境的因果动态

**实验证据**：
- VLA基线（仅动作监督）：PDMS ~60
- Vega（联合监督）：PDMS 87.9（NAVSIM v1）
- 性能提升：~47%

**机制分析**：
1. **中间表示学习**：
   - 预测未来图像迫使模型学习场景的中间表示
   - 这些表示对动作规划有用

2. **动态理解**：
   - 预测图像 = 预测场景如何演变
   - 理解对象运动、光照变化、遮挡

3. **多任务协同**：
   - 两个任务共享特征
   - 图像生成增强动作规划
   - 动作规划为图像生成提供约束

**推广意义**：
- 任何需要空间推理的任务都受益
- 从稀疏标签到密集监督的转变
- 可应用于3D重建、视频预测、运动规划

### 发现2：混合生成架构的优势

**纯自回归的问题**：
- 图像质量受限于tokenization
- 顺序生成导致高延迟

**纯扩散的问题**：
- 难以集成理解和推理
- 信息瓶颈

**集成Transformer的解决方案**：
- 自回归部分：理解和推理
- 扩散部分：高质量生成
- 统一架构：无信息瓶颈

**量化优势**：
- **图像质量**：接近纯扩散模型
- **推理效率**：比纯AR快（并行去噪）
- **理解能力**：继承自回归的推理能力
- **生成质量**：继承扩散的保真度

**Mixture-of-Transformers（MoT）**：
- **性能**：收敛更快，容量更高
- **模块化**：不同模态独立优化
- **可扩展**：易于添加新模态

**实验验证**：
- 动作专家 vs VLM模块：性能略有提升
- 动作专家 vs 扩散模块：性能显著提升
- 验证模块化设计的有效性

### 发现3：指令遵循的可扩展性

**从封闭集到开放式**：
- 传统：有限指令集（"左"、"右"、"停"）
- Vega：任意自然语言指令

**数据驱动的多样性**：
- 100,000+指令标注场景
- 两阶段自动化标注pipeline
- 结合VLM和基于规则方法

**泛化能力**：
- 训练指令的多样性使模型泛化到新指令
- 语义理解而非模式匹配
- 处理复杂组合指令

**验证实验**：
- 相同场景，不同指令
- 模型生成符合不同指令的不同轨迹和图像
- 证明灵活的指令遵循

**重要性**：
- 从"模仿"转向"理解"
- 系统适应用户意图而非仅复制专家行为
- 实现真正的个性化

### 发现4：交错序列的学习效率

**观察**：
- 交错图像和动作序列加速训练
- 更快收敛，更低损失

**原因分析**：
1. **动态学习**：
   - 图像 → 动作的交错展示因果关系
   - 模型学习动作如何影响视觉场景

2. **时序连贯性**：
   - 连续的视觉和动作序列
   - 学习长期依赖

3. **共享表示**：
   - 视觉和动作特征共享
   - 相互增强

**实验证据**：
- 预训练序列长度：2、4、6
- 更长序列 → 微调更快收敛
- 最终性能更好

**推广**：
- 任何需要时序推理的任务
- 视频理解、轨迹预测、多模态时序建模

### 发现5：世界模型作为物理引擎

**核心洞察**：
- 未来图像预测 = 简化世界模型
- 预测物理结果

**驾驶中的应用**：
- 车辆运动预测
- 其他代理行为预测
- 场景演变预测

**更广泛的意义**：
1. **物理理解**：
   - 不需要显式物理引擎
   - 从数据中学习物理规律

2. **模拟效率**：
   - 快速预测未来状态
   - 用于规划和决策

3. **泛化**：
   - 从见过的场景泛化到新场景
   - 学习可迁移的物理规律

**与Spatial AGI的关系**：
- 空间智能需要物理理解
- 世界模型提供"物理直觉"
- 用于规划、预测、控制

## 个人思考

### 最有趣的发现：密集监督的意外威力

**为什么有趣**：
- 直觉上，未来图像生成似乎与动作规划无关
- 但实验证明，预测图像显著提升了规划性能

**深层原因**：
1. **表征学习**：
   - 预测未来需要理解当前场景的深度表示
   - 这些表征对动作规划同样有用
   - 多任务学习导致更好的特征

2. **因果链条**：
   - 动作 → 未来图像
   - 预测正确的未来图像 = 执行正确的动作
   - 模型被迫学习"正确"的含义

3. **物理直觉**：
   - 预测图像 = 预测物理结果
   - 例如：左转后，场景应该显示左侧
   - 模型学习基本的物理和运动规律

**对比其他领域**：
- **NLP**：语言模型通过预测下一个token学习
- **计算机视觉**：通过掩码预测学习特征
- **驾驶/空间智能**：通过预测未来状态学习动态

**启示**：
- 如果想让AI理解环境，让它预测未来
- 这可能是通用的学习原则
- 适用于机器人、视觉、游戏AI等

---

### 最意外的结果：交错序列的显著优势

**初始预期**：
- 过去图像 + 当前指令 → 未来动作
- 历史动作可能不重要

**实验发现**：
- 交错图像和动作序列的预训练
- 加速微调收敛
- 提高最终性能

**深入思考**：

**原因1：显式时序建模**
- 模型看到：图像1 → 动作1 → 图像2 → 动作2 → ...
- 学习连续的因果关系
- 理解动作如何改变视觉观察

**原因2：动作的上下文**
- 当前动作依赖于之前动作
- 例如：加速后可以更快变道
- 历史动作为当前决策提供上下文

**原因3：训练-推理一致性**
- 推理时：看到过去图像和过去动作
- 预训练应该匹配
- 交错序列更好地模拟推理设置

**更广泛的应用**：
- **视频理解**：交错帧和字幕
- **机器人操作**：交错观察和动作
- **游戏AI**：交错游戏状态和玩家动作
- **对话系统**：交错对话历史和系统响应

**为什么不是标准做法**：
- 可能更难实现
- 需要修改数据pipeline
- 不明显的影响

**教训**：
- 不要忽视时序上下文
- 显式建模因果关系有帮助
- 训练和推理一致性很重要

---

### 最有价值的启发：统一架构的潜力

**为什么有价值**：
- 集成Transformer避免了信息瓶颈
- MoT设计实现了模块化和可扩展性
- 理解和生成的无缝集成

**关键启发**：

1. **避免信息瓶颈**：
   - 理解和生成应该是紧密集成的
   - 不应该通过少量潜在token传递信息
   - 这可能适用于多模态AI的所有领域

2. **模块化设计**：
   - MoT优于MoE用于多模态
   - 允许不同模态独立优化
   - 易于添加新模态

3. **统一的生成范式**：
   - AR + 扩散的结合
   - AR：结构、推理
   - 扩散：质量、多样性
   - 可以用于图像、视频、3D、音频

**对Spatial AGI的启示**：

**架构设计**：
- 统一的视觉-语言-空间-动作模型
- 每个模态有专门的模块
- 跨模态全局注意力

**扩展性**：
- 添加新的空间传感器（LiDAR、深度、热成像）
- 添加新的动作输出（控制信号、高级命令）
- 添加新的理解任务（分割、检测、重建）

**性能权衡**：
- 理解质量（AR）
- 生成质量（扩散）
- 推理效率（统一）

**潜在应用**：
- **统一空间AI**：
  - 感知、理解、推理、生成在一个模型
  - 避免pipeline的复合误差

- **多机器人协作**：
  - 每个机器人一个模块
  - 全局注意力实现协作
  - 统一的推理和规划

- **人机协作**：
  - 人类指令 + AI推理 + 人类反馈
  - 自然集成在统一架构中

### 未来方向：从驾驶到通用空间智能

**思考过程**：

Vega解决了特定的自动驾驶问题，但其原理具有更广泛的适用性：

1. **指令理解**：
   - 当前：驾驶指令
   - 未来：任何空间任务指令
   - 机器人导航、AR交互、虚拟操作

2. **世界建模**：
   - 当前：2D图像预测
   - 未来：3D场景、动态对象、物理效果
   - 3D重建、场景生成、物理模拟

3. **多模态融合**：
   - 当前：视觉 + 语言 + 动作
   - 未来：添加触觉、音频、LiDAR、IMU
   - 全面的空间感知

4. **时序推理**：
   - 当前：8帧未来
   - 未来：长期规划、多步推理
   - 复杂任务分解、策略规划

**潜在研究项目**：

**项目1：Vega-3D**
- 目标：3D场景理解和生成
- 方法：
  - 输入：多视图图像 + LiDAR
  - 输出：3D体素占用预测 + 轨迹规划
- 应用：机器人导航、场景重建

**项目2：Vega-Robot**
- 目标：机器人操作
- 方法：
  - 输入：RGB-D图像 + 语言指令
  - 输出：机械臂控制 + 物体状态预测
- 应用：家庭机器人、工业机器人

**项目3：Vega-AR**
- 目标：AR/VR交互
- 方法：
  - 输入：用户手势 + 语音 + 视觉场景
  - 输出：虚拟对象动作 + 视觉反馈
- 应用：协作设计、虚拟训练

**通用空间智能框架**：

```
输入：多模态传感器（视觉、语言、深度、触觉等）
      ↓
模块1：感知与理解（Transformer模块）
      ↓
模块2：世界建模（预测未来空间状态）
      ↓
模块3：规划与控制（生成动作序列）
      ↓
输出：动作 + 预测 + 解释
```

**关键挑战**：
1. **数据**：需要大规模多模态空间数据集
2. **评估**：如何衡量通用空间智能
3. **安全性**：真实世界部署的风险
4. **泛化**：从训练场景到新场景

**Vega的贡献**：
- 提供了具体的成功案例
- 验证了统一架构的可行性
- 展示了密集监督的价值

### 限制与改进方向

**当前限制**：

1. **传感器限制**：
   - 仅使用前视相机
   - 缺少多视图和深度信息
   - 改进：集成环视相机、LiDAR

2. **时间范围**：
   - 仅预测8帧未来（约4秒）
   - 改进：扩展到长期规划

3. **环境复杂性**：
   - 主要在NAVSIM仿真中测试
   - 改进：真实世界数据、更多样的天气/光照条件

4. **指令复杂性**：
   - 当前指令主要是单步
   - 改进：支持多步骤、嵌套指令

5. **推理速度**：
   - 扩散模型可能较慢
   - 改进：蒸馏、快速采样、并行推理

**潜在改进**：

1. **分层规划**：
   - 高级：语义路标点（"去超市"）
   - 中级：路径规划（"沿街道行驶"）
   - 低级：控制（"加速"）
   - Vega可以扩展到多层级

2. **主动感知**：
   - 主动选择观察角度
   - 例如：接近路口时转向摄像头
   - 提高信息效率

3. **多智能体交互**：
   - 当前：仅ego车辆
   - 未来：预测其他车辆的行为
   - 更真实的交通模拟

4. **元学习**：
   - 从少量新指令示例学习
   - 快速适应新用户风格
   - 个性化驾驶

5. **安全约束**：
   - 显式建模安全约束
   - 例如：保持最小距离
   - 约束优化确保可行性
