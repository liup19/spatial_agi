# ReMoGen - Real-time Human Interaction-to-Action Generation via Modular Learning from Diverse Data

**论文标题**: ReMoGen: Real-time Human Interaction-to-Reaction Generation via Modular Learning from Diverse Data  
**arXiv**: https://arxiv.org/abs/2604.01082  
**发表时间**: 2026年4月  
**作者**: Yaoqin Ye, Yiteng Xu, Qin Sun, Xinge Zhu, Yujing Sun, Yuexin Ma (ShanghaiTech University, Guangzhou Institute of Energy Conversion, CAS, University of Science and Technology of China, The Chinese University of Hong Kong, Nanyang Technological University)

## 执行摘要

ReMoGen是一个创新的研究框架，旨在解决**实时人类交互到反应生成**的核心挑战。论文提出了模块化学习方法，通过结合通用运动先验和领域特定的Meta-Interaction模块，在数据稀缺和异构监督条件下实现了强大的泛化能力。同时，通过Segment-level生成与Frame-wise细化相结合的策略，成功平衡了运动质量和实时响应性。在人类-人类、人类-场景和混合模态交互设置上的广泛实验验证了该方法的有效性。

**核心贡献**：
1. 提出了首个专注于实时交互到反应生成的模块化框架
2. 证明了在大规模单人生成数据集上预训练的通用运动先验可以高效迁移到交互领域
3. 实现了低延迟（0.042秒/帧）和高保真运动生成的平衡
4. 通过模块化设计实现了跨异构交互领域的泛化

**与Spatial AGI的关系**：
- 为Spatial AGI提供了核心的交互运动生成能力
- 展示了如何将多源空间线索整合到运动决策中
- 证明了模块化设计在复杂空间任务中的有效性

## 1. 核心问题与挑战

### 1.1 任务定义：实时交互到反应生成

**输入条件**：
1. **文本意图描述**（Text Intent）：
   - 高层次语义输入
   - 定义交互的目标和意图
   - 例如："我要走向那个人"

2. **其他代理的运动**（Others' Motion）：
   - 观察到的周围人的动作序列
   - 相对速度、接近方向
   - 社交上下文信息

3. **场景几何信息**（Scene Geometry）：
   - 3D空间布局
   - 障碍物位置
   - 可利用空间

4. **历史信息**（History）：
   - 自身运动历史
   - 过去交互序列

**输出**：
- **未来运动序列**（Future Motion Sequence）
- 连续的3D人体姿态序列
- 符合物理规律和语义约束

**约束条件**：
1. **实时性**：<0.1秒/帧（10 FPS）
2. **保真度**：高运动质量、物理合理性
3. **连贯性**：时间上平滑、空间上合理
4. **语义一致性**：与文本意图和交互上下文一致

### 1.2 挑战一：数据稀缺性和异质性

#### 1.2.1 问题背景

运动数据集在领域覆盖和监督模态方面存在巨大差异：

**大规模单人生成数据集**：
- HumanML3D：基于文本的3D人体运动生成
- AMASS：大规模动作捕捉数据库
- BABEL：身体、动作和行为标签数据集
- 典型特征：数据量大、标注质量高、标注类型简单

**小规模人类-人类交互数据集**：
- Inter-X：多样化的人类交互分析
- CMU Motion Capture Database：交互动作捕捉
- 典型特征：数据量小、标注复杂、领域特定

**人类-场景交互数据集**：
- LINGO：基于文本指令的场景交互合成
- TRUMANS：大规模动态人类-场景交互建模
- Ghost：开放词汇场景-文本上下文下的运动生成
- 典型特征：需要场景几何、交互类型多样

#### 1.2.2 挑战表现

**分布差异**：
```
单人生成数据：大量、分布简单、标注清晰
交互数据：少量、分布复杂、标注困难
领域鸿沟：分布差异巨大，迁移困难
```

**异质性**：
```
监督模态异质：
- 文本到运动（单人生成）
- 动作到动作（交互）
- 文本到交互（场景交互）
- 多模态监督（混合）

数据源异质：
- 动作捕捉（真实）
- 仿真生成（合成）
- 游戏数据（游戏化）
- 多种采集方式
```

**挑战影响**：
1. **难以学习统一先验**：不同领域的数据分布差异太大
2. **过拟合风险**：在单一领域训练的模型泛化能力差
3. **迁移困难**：无法有效利用跨领域知识
4. **缺乏有效策略**：如何利用所有可用资源是开放问题

#### 1.2.3 现有方法的不足

**端到端训练**：
- 在单一领域训练，其他领域性能差
- 无法利用大规模单人生成数据
- 泛化能力有限

**领域特定模型**：
- 每个领域单独训练
- 无法共享知识
- 资源利用率低

**简单迁移**：
- 直接用单人生成模型
- 没有适应机制
- 性能下降严重

### 1.3 挑战二：实时响应性

#### 1.3.1 实际应用需求

**虚拟角色动画**：
- 游戏中的NPC需要实时反应
- 电影制作需要快速迭代
- 虚拟会议需要自然交互

**人机协作机器人**：
- 机器人需要即时响应人类动作
- 协作任务需要流畅配合
- 安全要求高响应速度

**交互式AI系统**：
- 聊天机器人需要自然动作反馈
- 虚拟助手需要环境感知
- 实时交互要求严格

#### 1.3.2 实时性约束

**硬件约束**：
- GPU资源有限
- 需要在移动设备上运行
- 功耗和发热限制

**用户体验**：
- 延迟敏感（<100ms）
- 无感知延迟
- 流畅交互

**系统性能**：
- 高帧率（60 FPS）
- 低延迟
- 高吞吐量

#### 1.3.3 现有方法的权衡

**扩散模型**（Diffusion-based）：
```
优点：
✓ 高保真度
✓ 强生成能力
✓ 质量稳定

缺点：
✗ 计算开销大
✗ 需要多步去噪
✗ 推理慢（数百毫秒到数秒）
✗ 不适合实时交互
```

**自回归模型**（Autoregressive）：
```
优点：
✓ 响应较快
✓ 逐帧生成
✓ 累积误差可控

缺点：
✗ 长序列质量下降
✗ 运动漂移明显
✗ 误差累积
✗ 长期一致性差
```

**马尔可夫模型**：
```
优点：
✓ 计算简单
✓ 实时性好

缺点：
✗ 缺乏长期记忆
✗ 无法建模复杂依赖
✗ 质量较低
```

#### 1.3.4 核心权衡问题

**质量 vs 速度**：
```
追求高质量：
- 扩散模型
- 复杂架构
- 多步推理

追求速度：
- 简单模型
- 单步推理
- 轻量级网络

问题：如何在两者间找到最优平衡？
```

**保真度 vs 响应性**：
```
高保真度：
- 精确建模复杂动态
- 细粒度控制
- 长时间序列

高响应性：
- 快速生成
- 粗粒度推理
- 短时间序列

问题：如何保持长期运动质量的同时实现实时响应？
```

**稳定性 vs 灵活性**：
```
高稳定性：
- 精确建模
- 复杂约束
- 长时序

高灵活性：
- 快速适应
- 动态调整
- 多变场景

问题：如何保持长期稳定性的同时实现灵活适应？
```

## 2. ReMoGen 方法概述

### 2.1 核心思想：模块化学习

**设计哲学**：
- **解耦通用知识和领域特定知识**
- **模块化设计**：每个模块职责清晰
- **数据驱动**：充分利用现有数据资源
- **效率优先**：实时响应是核心要求

**整体架构**：
```
[输入层]
  ├─ 文本意图
  ├─ 其他代理运动
  └─ 场景几何

[通用先验层]
  └─ 从大规模单人生成数据学习

[交互适配层]
  ├─ Meta-Interaction HHI模块
  └─ Meta-Interaction HSI模块

[推理层]
  ├─ 片段生成器
  └─ 帧级细化器

[输出层]
  └─ 未来运动序列
```

### 2.2 三个核心组件详解

#### 组件一：通用单人生成先验

**功能定位**：
- 提供通用的运动动力学基础
- 编码大规模数据集学到的运动模式
- 为交互学习提供强大的初始化

**技术实现**：

1. **大规模数据集预训练**：
   ```
   数据集：HumanML3D
   训练目标：文本 → 运动序列
   学习内容：
   - 人体运动学结构
   - 运动时间动态
   - 语言-运动对齐
   - 运动多样性
   ```

2. **SMPL-X表示**：
   ```
   人体表示：
   - 身体姿态（Body Pose）
   - 手部姿态（Hand Pose）
   - 根运动（Root Motion）
   - 表情（Expression）
   - 全局旋转（Global Rotation）

   维度：D ≈ 103 + 22 + 30 = 155
   ```

3. **潜在空间扩散**：
   ```
   压缩运动表示：
   高维运动 → 低维潜在

   扩散过程：
   运动序列 M
     → 编码器 Enc(M)
     → 潜在表示 z
     → 添加噪声
     → 扩散模型生成
     → 解码器 Dec(z)
     → 运动序列

   优势：
   - 压缩表示
   - 去噪生成
   - 条件控制
   - 质量保证
   ```

4. **冻结策略**：
   ```
   训练阶段：
   - 大规模单人生成数据上预训练
   - 学习通用运动先验
   - 固定模型参数

   适配阶段：
   - 冻结先验网络
   - 训练Meta-交互模块
   - 不更新先验参数

   优势：
   - 保持预训练知识
   - 避免灾难性遗忘
   - 提高训练稳定性
   ```

**性能表现**：
```
在Inter-X上（仅使用先验）：
- FID: 3.735（相比GT的0.000差距明显）
- R-Precision: 0.231（较低）
- MM-Dist: 5.736（较大）
- Diversity: 3.235（一般）

结论：
✓ 能生成合理运动
✗ 无法生成协调交互
✗ 缺乏交互特定知识
```

#### 组件二：Meta-交互模块

**功能定位**：
- 将通用先验适配到特定交互领域
- 注入交互特定知识
- 实现领域特定的调制信号

**设计原理**：

1. **独立训练策略**：
   ```
   HHI模块：
   - 在Inter-X上训练
   - 学习人-人交互知识
   - 输入：文本 + 其他人的动作
   - 输出：协调的交互运动

   HSI模块：
   - 在LINGO上训练
   - 学习人-场景交互知识
   - 输入：文本 + 场景几何
   - 输出：场景感知的运动

   不联合训练：
   - 每个模块独立训练
   - 避免梯度冲突
   - 减少计算开销
   ```

2. **文本无关性**：
   ```
   模块不依赖文本：
   - 直接从运动输入学习
   - 聚焦于交互模式
   - 可重用于不同文本

   文本的作用：
   - 仅在通用先验层使用
   - 提供高层次语义指导
   - 模块专注于领域适配
   ```

3. **上下文编码**：

   **其他代理编码器**（TCN-based）：
   ```
   TCN架构：
   - 时间卷积层
   - 多尺度感受野
   - 捕获时序依赖

   输入：其他人的运动序列
   输出：交互线索特征
   关键信息：
   - 相对速度
   - 接近方向
   - 运动方向
   - 空间距离
   - 关系类型（接近、远离、追逐、躲避）
   ```

   **场景编码器**（ViT-based）：
   ```
   Vision Transformer：
   - 自注意力机制
   - 全局视野
   - 捕获空间关系

   输入：体素化3D场景
   输出：场景线索特征
   关键信息：
   - 几何结构
   - 可利用空间
   - 障碍物位置
   - 空间关系
   - 场景语义
   ```

4. **Meta-交互块**：
   ```
   结构：
   输入：ego特征 + 上下文线索
     ↓
   自注意力层
     ↓
   交叉注意力层
     ↓
   FiLM调制
     ↓
   前馈层
     ↓
   输出：调制后的ego特征

   细节：
   - 自注意力：refine ego特征
   - 交叉注意力：从上下文中提取信号
   - FiLM调制：应用调制参数
   - 前馈层：生成最终特征
   ```

   **调制机制**：
   ```
   FiLM (Feature-wise Linear Modulation):
   
   h_mod = (1 + tanh(γ)) ⊙ h' + tanh(β)
   
   其中：
   - h': ego特征
   - γ: 比例调制参数
   - β: 偏置调制参数
   - ⊙: 元素级乘法
   - tanh: 非线性激活

   优势：
   - 保持特征结构
   - 灵活控制分布
   - 计算高效
   - 容易优化
   ```

**训练细节**：
```
损失函数：
- 重建损失：MSE(M_pred, M_gt)
- 时序差分损失：捕获运动动态
- 辅助损失：多任务学习

训练参数：
- 优化器：AdamW
- 学习率：1e-4
- 批大小：1024
- 迭代次数：65k
- 梯度裁剪：1.0
- EMA：0.999
```

**推理机制**：
```
组合推理：
Δ_total = Σ(α_i * Δ_i)

其中：
- Δ_i：第i个模块的调制信号
- α_i：用户定义的权重系数
- Σ：累加

权重选择：
- HHI权重：控制社交反应强度
- HSI权重：控制场景适应强度
- 可根据应用调整

归一化：
- L2范数钳制
- 防止数值不稳定
- 保证特征范围
```

**性能表现**：
```
在Inter-X上（使用HHI模块）：
- FID: 0.181（显著优于Prior Only的3.735）
- R-Precision: 0.464（大幅提升）
- MM-Dist: 4.076（接近最优）
- Diversity: 3.911（提高）
- Latency: 0.042秒/帧（实时）

在LINGO上（使用HSI模块）：
- FID: 1.201（优于TRUMANS的4.731）
- R-Precision: 0.530（接近最优）
- MM-Dist: 3.408（最佳）
- Diversity: 7.421（最高）
- Latency: 0.042秒/帧（实时）
```

#### 组件三：帧级片段细化模块

**功能定位**：
- 实现低延迟响应
- 逐帧更新运动预测
- 平衡质量和速度

**设计动机**：

**问题：片段级生成的局限**
```
Segment-level生成：
- 一次生成8帧
- 每8帧更新一次
- 延迟：8帧×帧间隔

优势：
✓ 高质量
✓ 平滑连贯

局限：
✗ 延迟较高
✗ 响应慢
✗ 无法立即响应新线索
```

**问题：帧级生成的局限**
```
Frame-level生成：
- 每帧独立生成
- 延迟：1帧×帧间隔

优势：
✓ 响应快
✓ 实时更新

局限：
✗ 质量差
✗ 不连贯
✗ 计算量大
```

**FWSR解决方案**：
```
结合两种方法的优点：

Segment-level生成：
- 负责长时域预测
- 保证整体质量
- 平滑连贯

Frame-wise细化：
- 负责短时域修正
- 实时响应
- 细化细节

结果：
✓ 高质量
✓ 实时响应
✓ 平滑连贯
```

**技术实现**：

1. **轻量级细化网络**：
   ```
   结构：
   输入：z₀ + 动态上下文
     ↓
   轻量级Meta-交互块
     ↓
   调制后的潜在表示
     ↓
   解码（利用原始历史）

   与主模块的区别：
   - 网络更小
   - 参数更少
   - 计算更少
   - 专门为细化优化
   ```

2. **动态上下文**：
   ```
   每帧的输入：
   X_dyn^(f) = concat(M_h^(f-1), X_dyn^(f))

   其中：
   - M_h^(f-1): ego的最近历史
   - X_dyn^(f): 新观察到的交互线索
   - concat: 拼接操作

   作用：
   - 提供最新的交互信息
   - 指导当前帧的细化
   - 更新运动方向
   ```

3. **逐帧细化流程**：
   ```
   算法：
   for f = 1 to F-1:
       1. 提取最近窗口
          X_dyn^(f) ← X_dyn[:, -H:, :]
       
       2. 细化潜在
          z̃_f ← FWSR(z₀, M_h^(f-1), X_dyn^(f))
       
       3. 解码
          M̃_f ← D_θ(M_h^(0), z̃_f)
       
       4. 更新历史
          M_h^(f) ← concat(M_h^(f-1)[:, 2:H, :], m^(f))
   
   其中：
   - z₀: 初始片段潜在（主生成器预测）
   - M_h^(f-1): 更新的历史窗口
   - m^(f): 当前细化后的帧
   ```

**训练细节**：
```
训练方式：
- 与通用先验独立训练
- 保持先验和Meta-交互模块冻结
- 仅训练FWSR模块

训练迭代：
- 迭代次数：65k
- 批大小：1024
- 学习率：1e-4
- 优化器：AdamW

目标：
- 最小化与GT的差异
- 保持与Segment生成的一致性
- 提高响应性
```

**性能表现**：
```
对比实验：

Baseline: Segment
- FID: 0.181
- Latency: 0.042秒/帧
- 质量：高
- 响应：中等

Sliding Window: Frame-level diffusion
- FID: 4.136
- Latency: 0.305秒/帧
- 质量：低
- 响应：快

Ours: Segment + FWSR
- FID: 0.166（优于Baseline）
- Latency: 0.047秒/帧（略高于Baseline）
- 质量：更高
- 响应：更快

关键发现：
✓ 质量提升（FID降低）
✓ 响应性提高（0.047 vs 0.042，仍然实时）
✓ 平衡优化（质量-速度权衡得到改善）
```

## 3. 算法原理详解

### 3.1 问题形式化

**符号定义**：
```
W: 文本意图（word embeddings）
M_h^i: ego的历史运动窗口（history length H）
M_f^i: ego的未来片段（future length F）
c_others: 其他代理的上下文特征
c_scene: 场景的上下文特征
z_t: 扩散过程中的潜在表示
z₀: 去噪后的潜在表示
M: 生成的运动序列
```

**生成过程**：
```
给定：
- 文本意图 W
- ego的历史 M_h^i
- 其他代理的运动 X_others
- 场景 X_scene

生成：
1. 编码文本
   w = Enc_text(W)

2. 初始片段生成
   z₀ = G_ψ(z_t, t, M_h^i, w)
   M_f^(0) = D_θ(M_h^i, z₀)

3. 应用Meta-交互模块
   c_others = Enc_others(X_others)
   c_scene = Enc_scene(X_scene)
   h = Meta-Block(M_h^i, c_others, c_scene)
   z₀ = Modulate(z₀, h)

4. 逐帧细化
   M_f = FWSR(z₀, M_h^i, X_dyn)
```

### 3.2 数学公式详细推导

**片段级生成**：
```
输入：M_h^i ∈ ℝ^(H×D), W ∈ ℝ^(T_w×D_w)

1. 文本编码
   w = Enc_text(W) ∈ ℝ^(T_w×D_w)

2. 扩散去噪
   z_t = noise_sample()  # 添加噪声
   for t = T to 1 step -1:
       z_{t-1} = G_ψ(z_t, t, M_h^i, w)

3. 解码
   z₀ = z_{T-1}
   M_f^(0) = D_θ(M_h^i, z₀) ∈ ℝ^(F×D)

其中：
- D_θ: VAE解码器
- G_ψ: 潜在去噪器
- H = 历史长度
- F = 未来长度
- D = SMPL-X表示维度
```

**FiLM调制**：
```
输入：
- ego特征 h ∈ ℝ^(L×D)
- 调制参数 γ ∈ ℝ^(L×D)
- 调制参数 β ∈ ℝ^(L×D)

输出：
h_mod = (1 + tanh(γ)) ⊙ h + tanh(β)

展开：
h_mod_i = (1 + tanh(γ_i)) * h_i + tanh(β_i)

其中：
- ⊙: 元素级乘法
- tanh: 双曲正切激活函数
- i: 序列索引

优势：
- 保持h的结构
- 灵活控制分布
- 计算高效
```

**FWSR细化**：
```
输入：
- z₀: 初始片段潜在
- M_h: 初始历史窗口
- X_dyn: 动态上下文

输出：
- z̃_f: 细化后的潜在

算法：
1. 初始化
   m^(0) = M_f^(0)[:, 1, :]
   M_h^(0) = concat(M_h[:, 2:H, :], m^(0))

2. 逐帧细化
   for f = 1 to F-1:
       a. 提取动态窗口
          X_dyn^(f) = X_dyn[:, -H:, :]
       
       b. 细化潜在
          z̃_f = FWSR_block(z₀, M_h^(f-1), X_dyn^(f))
       
       c. 解码
          M̃_f = D_θ(M_h^(0), z̃_f)
       
       d. 提取帧
          m^(f) = M̃_f[:, 1+f, :]
       
       e. 更新历史
          M_h^(f) = concat(M_h^(f-1)[:, 2:H, :], m^(f))
   
3. 返回完整片段
   M_f = concat(m^(0), m^(1), ..., m^(F-1))

其中：
- FWSR_block: 轻量级Meta-交互块
- M_h^(0): 始终使用初始历史
- 保持长时域一致性
```

**组合推理**：
```
输入：
- Δ_HHI: HHI模块的调制信号
- Δ_HSI: HSI模块的调制信号
- α_HHI: HHI权重
- α_HSI: HSI权重

输出：
- Δ_total: 融合后的调制信号

计算：
Δ_total = α_HHI * Δ_HHI + α_HSI * Δ_HSI

约束：
||Δ_total||_2 ≤ C  # L2范数钳制

其中：
- ⊕: 线性组合
- ||·||_2: L2范数
- C: 钳制阈值（如1.0）

应用：
z_final = Modulate(z₀, Δ_total)

归一化：
Δ_normalized = Δ_total / ||Δ_total||_2
z_final = Modulate(z₀, Δ_normalized * C)
```

### 4.2 评估指标

**运动质量指标**：

**1. FID（Fréchet Inception Distance）**：
```
定义：
FID = ||μ_p - μ_q||² + Tr(Σ_p + Σ_q - 2√(Σ_p Σ_q))

其中：
- μ_p: 生成分布的均值
- μ_q: 真实分布的均值
- Σ_p: 生成分布的协方差
- Σ_q: 真实分布的协方差

意义：
- 衡量生成质量
- 值越小越好
- 综合考虑分布差异

基准：
- GT: 0.000（完美）
- 良好：< 2.0
- 一般：2.0 - 5.0
```

**2. R-Precision（Recall Precision）**：
```
定义：
P(k) = 概率所有前k个最近邻中GT的正确率

R-Precision(Top-k):
- Top-1: 100%
- Top-3: 75%
- Top-5: 60%

意义：
- 衡量语义对齐
- 值越高越好
- 越小越精准

基准：
- GT: > 0.8
- 良好：0.6 - 0.8
- 一般：0.4 - 0.6
```

**3. MM-Dist.（Movement Distance）**：
```
定义：
MM-Dist = 平均运动到文本的距离

意义：
- 衡量运动多样性
- 值越小越好
- 避免重复运动

基准：
- GT: 最小
- 良好：< 4.0
- 一般：4.0 - 6.0
```

**4. Diversity**：
```
定义：
Diversity = 随机采样生成的运动与GT的欧氏距离的均值

意义：
- 衡量多样性
- 值越大越好
- 避免单调

基准：
- GT: 最大
- 良好：> 3.0
- 一般：2.0 - 3.0
```

**5. Peak Jerk（平滑性）**：
```
定义：
Jerk = 角加速度的导数

Peak Jerk = max(|jerk|)

意义：
- 衡量运动平滑性
- 值越小越好
- 避免突变

基准：
- GT: 最小
- 良好：< 0.3
- 一般：0.3 - 0.5
```

**6. Collision (%)**：
```
定义：
Collision = 生成运动中发生碰撞的概率

意义：
- 衡量物理合理性
- 值越小越好
- 避免穿透

基准：
- GT: 0%（完美）
- 良好：< 1%
- 一般：1% - 5%
```

**实时性指标**：

**7. Latency（延迟）**：
```
定义：
Latency = 每帧的端到端推理时间

单位：秒/帧

意义：
- 衡量实时性
- 值越小越好
- <0.1秒为实时

基准：
- 实时：< 0.1秒/帧
- 可接受：0.1 - 0.3秒/帧
- 不实时：> 0.3秒/帧
```

#### 7.1.2 算法原理详解

**原理1：潜在空间扩散**

**为什么用扩散？**
```
优势：
✓ 高质量生成
✓ 复杂分布建模
✓ 条件控制
✓ 理论保证

实现：
- 运动序列 → 潜在表示
- 添加噪声
- 扩散去噪
- 解码生成

优势：
- 压缩表示
- 高效生成
- 质量保证
```

**原理2：FiLM调制**

**工作原理**：
```
输入：特征 h + 调制参数 γ, β

过程：
1. 自注意力 refine h → h'
2. 交叉注意力提取信号 → context
3. MLP生成 γ, β
4. FiLM调制：h_mod = (1+tanhγ)⊙h' + tanhβ

输出：调制后的特征

优势：
- 保持结构
- 灵活控制
- 计算高效
```

**原理3：模块化推理**

**组合推理**：
```
输入：
- Δ_HHI: HHI模块调制信号
- Δ_HSI: HSI模块调制信号
- α_HHI: HHI权重
- α_HSI: HSI权重

计算：
Δ_total = α_HHI·Δ_HHI + α_HSI·Δ_HSI
Δ_normalized = Δ_total / ||Δ_total||₂

应用：
z = Modulate(z₀, Δ_normalized)

优势：
- 灵活组合
- 自适应权重
- 稳定输出
```
